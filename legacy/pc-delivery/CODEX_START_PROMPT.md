# 给接收方Codex的启动提示词

把下面内容复制到同事的Codex任务中，并将工作目录设为本交付包根目录。不要把原作者电脑路径当作同事本机路径。

---

你现在接手“RK3576目标检测、人脸检测/角度估计、自动拍照”项目。负责人目标是在独立RK3576板卡上实现三类端侧功能，未来连接带摄像头云台，左右目标角度自动拍照。我的电脑是Windows，Linux环境是WSL2 Ubuntu22.04。

请先完整阅读当前目录README.md、TECHNICAL_HANDOFF.md、VALIDATION.md、VERSION和manifests/source_inventory.json，再检查实际代码；不要回读原作者超长聊天，也不要假设你能访问原作者电脑。

当前交付版本V0.0.1。pc_demo是最新版真实模型电脑实现，包含最新版web页面：旧仪器V5检测/接触点、人脸七区、YuNet人脸锁定、FSA-Net角度、3帧中值+EMA防抖、每秒角度展示、可调目标角度/±误差/倾斜上限/稳定时间、同帧自动拍照与重拍。模型都随包提供，不要重复下载。负责人说的人脸识别当前是检测/锁定，并非身份认证；不要声称实现了身份识别。

先做以下工作：

1. 只读检查当前目录和Git状态，不覆盖已有修改。运行tools/verify_package.py，确认模型及源码完整。
2. 核实实际WSL发行版名称、Python3.10、GPU、摄像头和网络权限。在本包独立.venv中建立CPU或CUDA环境，不修改系统Python、其他项目环境或全局驱动。首次下载依赖前遵守当前用户/环境权限。不要混装onnxruntime与onnxruntime-gpu。
3. README中的requirements是固定顶层安装入口及原环境快照，不是已在你机器验收的锁。遇到版本不可获得、ABI、CUDA或OpenCV冲突，保存报错，做最小范围兼容修复并记入日志，不默默升级全套。
4. 跑13项Python回归、JS显示刷新测试（有Node时）和真实模型烟测；启动服务，用Windows Edge/Chrome打开http://127.0.0.1:8876/。先让用户看到本包网页，不替换成旧网页。
5. 引导用户做左右30°±5°、45°±5°实拍、旧仪器与人脸同框、镜像、模糊、失锁、多人、过期和参数修改验证。角度平滑不等于精度提升，拍照必须满足稳定值及当前原始帧，不要通过删除门禁或伪造结果解决拒拍。
6. 记录实际providers、版本、哈希、环境、测试结果、角度偏置和失败原因；建立本机环境锁。CPU回退不能宣称CUDA或NPU。禁止把电脑推理当板卡推理。

电脑闭环通过后，继续RK3576计划，但先检查板卡是否接入及部署授权。如果没有板卡，继续做可离线完成的契约测试、代码抽象和迁移计划，不虚报板端验证。

rk3568_reference仅是旧板源码与证据，旧Runtime/Toolkit2是1.5.2，不能原样套到RK3576。旧板100帧通过但30分钟约10分钟挂起，根因未定；不是正式稳定版本。旧部署脚本含推送/停止等副作用，默认只读，严禁未核对设备就运行。

本包提供RKNN友好的opset12设备原始三尺度ONNX和接触点ONNX，可作为3576转换起点。SDK、工具链、RKNN、校准图片、金标准图片和训练checkpoint不在包内；需要时先请求项目方，不得编造或用测试集冒充训练校准集。MediaPipe.task不是可直接转RKNN的ONNX。

实板阶段：只读盘点SDK/NPU驱动/runtime/摄像头/云台；按官方兼容资料建立隔离RK3576转换环境；先FP16再INT8，逐模型对拍；实现板端C++推理、滤波门禁、同帧拍照、统一坐标/参数/版本接口；云台先dry-run，明确机械限位与失脸停机，实际转动前取得授权。不要刷固件、改系统分区或改驱动作为默认动作。

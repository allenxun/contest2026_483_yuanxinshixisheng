# 语音控制整机测肤整合

目标：沿用BLE App配网、云端流式ASR和最大档TTS，把已有跟踪/角度检测/三视图与18085业务后端接通。本文为源码及实际OpenAPI核对后的实施合同，不代表整机真机已跑通；本轮未发送云台运动、拍照或照片上传命令。

## 用户流程

普通对话 → “启动云台” → 开启既有相机/跟踪 → “测肤” → 角度与稳定性判断 → 正/左/右三张有效照片 → 上传 → 提示“照片已提交，正在分析” → 查询任务 → 播报结果。

任意本地工作阶段收到“停止云台”：取消当前任务，阻止后续运动和拍照，停止跟踪并保持当前位置，保留WiFi/ASR/TTS，退出到对话模式。已被后端受理的分析不冒称取消；停止运动不等于回零或断电。现有MCU协议无动作ACK，不能用UART发送成功冒称实测停止。

## 统一控制入口

ASR仅将final交给意图路由；partial用于界面显示。固定命令优先于聊天，明确匹配“启动云台”“开始测肤/测肤”“停止云台/停止测肤”，含否定或讨论句不按关键词子串直接执行。相同ASR句子以会话/句子ID去重。

会话控制器管理CHAT、TRACKING、CAPTURING、UPLOADING、WAITING_REPORT、STOPPING状态。每次任务分配task_epoch；停止先增加epoch并取消工作，再停止跟踪；旧照片、旧回调和迟到响应不能恢复已停止动作。控制器是唯一串口/硬件命令拥有者，ASR、相机、TTS为独立任务，不能让长时间拍照阻塞停止命令。

普通文本交给后端聊天接口。当前只有回声测试，不能把回声状态称为自由聊天；后端聊天合同仍待提供。

## 已核对的后端合同

后端 http://10.3.3.170:18085：先POST /api/v1/gimbal-sessions获取设备token；APP token不能替代。
POST /api/v1/skin-assessment-tasks 使用multipart/form-data：metadata为JSON，front/left/right为本轮真实照片，Idempotency-Key必填。metadata.photoVersion="1"，captureSessionId为本轮采集标识，consentEvidenceRef引用真实同意记录，不能编造。单图上限10MiB、总计32MiB为当前开发配置。

202表示queued受理，不代表分析完成。GET /api/v1/skin-assessment-tasks/{taskId}查询状态，按真实响应处理report_ready/needs_retake等状态；补拍PUT /api/v1/skin-assessment-tasks/{taskId}/photo-versions/{photoVersion}，严格遵守版本和指定视角。照片必须与采集帧/视角对应，不能把预览占位图上传。

## 开发验收顺序

1. 不动作的意图与任务控制器回归：重复指令、否定句、忙碌时重复测肤、停止打断、迟到回调。
2. 统一串口拥有者及摄像头重复启动/停止；保持语音与WiFi，旧限位/标定不改变。
3. 真机启动→停止→聊天→再次启动；确认停止不会被后续视觉结果覆盖。
4. 一轮三视图采集与正确文件确认，再用真实设备认证上传，拿到taskId。
5. 后端结果回报、补拍、断网重试；最后串接流式自由对话。

本轮仅整理可执行的整合路径与真实合同，未验收相机/音频/WiFi并发、整机停止或后端上传。

# ASR 重复调用异常与 TLS 候选修复

## 已观察到的故障

`voice-asr-microphone-20260911` 第一轮麦克风识别输出了文字，但与目标句不符。第二轮在首个推理块完成前出现 Data Abort，`FAR=0x1880`、`ELR=0x40b64238`。实际加载 ELF 将该地址解析到 `MlasGemmQuantScaleSumBuffer`，后续调用链为量化 MatMul 和 ORT Run；不能把它描述为已经定位到模型文件错误。

原始日志：`work-in-progress/native-asr-microphone/record-asr-20260911-180524.log`。异常后自动启动了 eMMC 原有基础镜像，本轮没有刷写存储。

## 已确认的底层事实

当前 AArch64 GCC 13.4.0 配置包含 `--disable-threads --disable-tls`，报告 `Thread model: single`。实际固件的 `__emutls_get_address` 从控制结构偏移 16 读取、缓存一个共享指针，没有按线程查找数据。

MLAS 使用 `thread_local ThreadedBufSize` 和带析构的 `thread_local ThreadedBufHolder`。原实现只按缓存大小判断是否分配，不检查 holder 是否为空。共享缓存与线程析构结合是本次空指针故障的重点修复方向；最终仍需连续真机运行验证，主机测试不代替修复验收。

## 候选范围

候选位于 `work-in-progress/native-emutls-fix/`，尚未作为通用 BSP 功能验收：

- 用一个 NuttX 全局任务 TLS 槽定位当前任务组的 pthread key；各线程通过该 key 保存自己的 emutls 块。
- 实现 `__cxa_thread_atexit` / `__cxa_thread_atexit_impl`，在释放 emutls 块之前按 LIFO 调用本线程 C++ 析构函数。
- 保留 GCC 控制结构 ABI 和初始模板、对齐语义；不将共享控制结构改写成某个线程的地址。
- 限制每线程块数、单块大小和析构次数；不支持动态卸载共享库，当前固件为静态链接。
- ASR 测试入口增加互斥，避免两个命令并发使用共享模型池。

NuttX 当前退出顺序已核对：线程 TLS 析构 → atexit → 任务组 TLS 析构。涉及动态库卸载、异常终止任务、退出函数再次创建 TLS 的情况不在本轮验收范围。

## 验证

第二轮主机报告：`work-in-progress/native-emutls-fix/host-20260911-182147/result.json`。O0、O2、ASan/UBSan 均通过；模拟 32 个任务组、64 个线程，检查独立地址、初值、对齐、128 次 LIFO 析构、析构中访问 TLS、非法对齐拒绝。它使用主机 pthread 和模拟的任务组接口。

首轮原生编译暴露 `struct group` 与 NuttX 系统头同名，以及内建函数原型告警；已更名并采用 `void *(void *)` 签名。失败日志保留，修改后重跑上述主机测试。

`voice-tls-20260911` 独立固件构建、ELF 范围及异常表检查通过，BIN SHA256：`86631d2091e9b5c2a155e2a83d28eeeebca860706d557264c667d4bf73a365df`。真机线程隔离和连续两次 ASR 验收仍待执行，不能宣称 BUG 已修复。

## 后续真机结果：18:55 起

上述待执行状态由本节覆盖。OTG 最终包、固件及两个完整模型 CRC 全部通过，RAM 启动成功。连续两次独立 `k7voice asr-model &` 均出现 `TLS_CHECK PASS workers=2 destructors=2 main_value=123`，完整识别输出相同，耗时分别 42.250、42.074 秒。两次模型池峰值均 468101988 字节，释放后 live=0，failures=0。证据与原始日志哈希在 `work-in-progress/native-emutls-fix/board-repeat-acceptance.json`。

这证明此前第二次调用崩溃的有限复现测试已通过，不替代长期运行或所有异常退出测试。随后提示音、3 秒麦克风采集、真实 ASR 也完成，26.830 秒输出“泰车联网开车”；目标是“开始联网”，因此麦克风准确性仍不通过，不执行联网指令。录音 left_nonzero=12000/48000，周期性零样本仍是待解决问题。未刷 eMMC，未恢复验收 Wi-Fi/BLE。

同一 voice-tls 镜像补跑已有 loopback-guard：result=0，128 对原始字，RXCSR 00400fff→00500fff→00400fff，停止和恢复返回0。仍观察到成对零值，说明等待两个FIFO都有数据没有消除异常；串口输出存在缺字，不能据此给出完整256字统计。原始 guard 日志保存在 native-emutls-fix，未改写麦克风缓冲。下一项有区分力的实验是独立250微秒暂停RXDR取数并记录FIFO累积，尚未实现/执行；不重复旧清零、复位或音量试验。

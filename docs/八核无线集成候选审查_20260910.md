# 八核无线集成候选

本轮已验证独立八核调度，实际板端随后恢复 emmc-vfs 单核版本；无线恢复证据在 `evidence/smp-eight-20260910/recovery-acceptance.json`。新的 `smp-service-20260910` 是独立编译候选，不能借用单核无线结果当作多核验收。

## 配置与调度边界

配置从已验证的 emmc-vfs 功能集建立，启用 SMP、NCPUS=8 和明确命令执行的 k7smp。普通初始线程默认亲和性为0x1，计算线程须显式请求其他核心。SDK `sched/init/nx_start.c` 用 SMP_DEFAULT_CPUSET 初始化任务亲和性；`sched/task/task_setup.c` 继承父线程亲和性，`sched/pthread/pthread_create.c` 允许属性中的非零亲和性覆盖。上板仍须用 ps 与实际线程采样确认，配置本身不算运行证据，也不证明中断自动绑定CPU0。

完整单核配置含独立的 CONFIG_NCPUS=1。第一次候选只修改 SMP_NCPUS 导致每核TCB数组仍为1，编译器在 nx_start.c 拦下越界。已保留 failed-attempt-01.log，统一两个CPU数并在构建输出断言两者均为8。第二次同步检查拒绝此前项目自己生成的旧配置；以首次本地配置哈希建立仅此文件的来源记录，不接受任意SDK文件。

## 已读无线同步点

- skw_rk3576.c 的SDIO总线端口使用host mutex，MMIO读写有屏障；这不是全部调用路径已无竞态的证明。
- k7radio_main.c 的接收分派在g_wifi_state内调用fw_wifi_net_slot，WPA/EAPOL队列与数据重放状态共享该锁。
- skw_netdev.c 使用队列锁和租约锁；prov_service.inc 使用g_prov_lock保护连接、事务与订阅，并使用信号量协调通知。
- wifi_ip_service.inc 的启动/退出所有权、g_wifi_ip_rejects初始化、清理后done信号与active标志发布顺序仍需专门复核；不能因为单核时成功就开放语音与BLE两个独立调用方。
- BLE协议栈、USB/xHCI、UART、NPU和模型arena尚未完成全路径SMP审查。默认CPU0是阶段性范围约束，不替代同步修复。

## 下一次上板的验收范围

1. 校验当前源码、ELF段及实际配置；预先准备已验证单核镜像恢复路径。
2. RAM启动后确认8个IDLE、服务线程亲和性及NSH响应，再执行一次k7smp；不运行云台、摄像头和NPU旧测试。
3. 启动无线，验证BLE请求、真实WPA2/DHCP事件、事务ID及网关回包；与显式绑核计算任务并发时记录断连、拒收和丢包。
4. 保留失败并恢复已验证版本。短时通过只能记为候选回归，不记为长稳或整机完成。

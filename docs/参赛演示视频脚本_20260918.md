# VelaVision 参赛演示视频脚本

## 官方硬性信息

官方总览要求提交不超过 5 分钟的演示视频，格式可用 mp4、mov 等常见格式；同时提交作品介绍文档和专属仓地址。见官方《大赛总览》的“作品提交要求”。

新硬件适配指引要求作品能在目标硬件启动并正常运行，至少有 UART 控制台输出，并提交 defconfig、板级初始化和必要驱动适配代码。因此录到板端 NSH 启动和命令输出是很有价值的真机证据，但官方没有规定必须把 NSH 作为单独视频片段。

## 建议成片顺序（约 4 分钟）

1. **0:00–0:25，硬件与启动**
   - 拍 K7 板、摄像头、云台和喇叭。
   - 串口窗口显示 openvela 启动日志、NSH 提示符和一条只读状态命令。
   - 口述“系统在 K7 上启动，下面演示设备能力”。不要展示 credential、session token 或 API key。

2. **0:25–0:55，代码与移植对应关系**
   - 快速展示仓库中的 `board/`、`app/k7host/`、`app/k7radio/`、`app/k7agent/` 和 `logs/`。
   - 展示一次构建命令或构建产物校验，不要长时间停留在编译过程。

3. **0:55–1:25，蓝牙配网与联网**
   - App 扫描到 VelaVision K7，选择 Wi-Fi 并提交密码。
   - 板端或 App 显示联网成功和 IP；语音提示使用已缓存的“联网成功”。

4. **1:25–2:10，实时视觉与云台**
   - 显示实时视频、人脸框和云台跟随。
   - 说官方统一唤醒词“你好，openvela”，展示“openvela 云台已启动”。
   - 只展示一次完整动作，避免剪辑掩盖失败。

5. **2:10–3:20，三视图测肤闭环**
   - 语音触发皮肤检测。
   - 依次展示正面、左侧、右侧提示和拍摄完成状态。
   - 展示三张照片上传、任务进入 `queued/analyzing`，随后到 `report_ready`。
   - 展示真实 brief 报告被分段 TTS 播报，并回到人脸跟随待机。

6. **3:20–3:50，工程证据与边界**
   - 展示一小段测试结果、日志目录和真机照片/串口日志。
   - 若视频流或后端讲解流在当前版本仍有已知限制，应在字幕中如实标注版本和限制，不要用历史 mock 或旧状态冒充当前通过。

## 拍摄注意事项

- 一镜到底优先；必要剪辑只剪空白等待，不剪掉命令、状态变化或失败提示。
- NSH 窗口可以录，但遮住设备 token、Wi-Fi 密码、内网地址中不必要的部分和任何 API key。
- 视频里同时保留“板端实物 + 串口 + App/联调界面”三类证据，评委更容易确认不是电脑端模视频已经录好你可以帮我剪辑或者看一下吗？拟。
- 先录能稳定复现的功能。当前新后端真实上传、任务轮询、brief 报告和 TTS 已验证；报告讲解 SSE 仍受后端缺少 `pores/spots/surface_gloss` 三组评分影响，设备会安全降级播报真实 brief。

# 原生 C++ 运行库接入

目的：为原生 openvela 上静态链接 llama.cpp 提供实际运行库门禁。此候选不含语言模型，不代表 Agent 部署成功。

新增 `app/k7cxx/`，显式命令 `k7cxx`，每次启动最多执行一次。检查全局动态构造、vector/string、异常传播和 RAII 析构、64 字节对齐的 4KiB 分配读写、std::thread、mutex/condition_variable 和单调时间，并报告 off_t 与指针宽度。等待工作线程最多3秒，串口观察最多10秒；超时后的共享对象仍保留静态生命周期。它不访问模型文件、不操作无线或执行机构、不写存储，也不证明线程最终退出清理或长期无泄漏。

独立配置 `velavision_cxx_tls_local` 在既有八核无线配置上启用 C++17、LLVM libc++/libc++abi（配置版本17.0.6）、异常和 RTTI、线程 TLS 8槽及任务 TLS 8槽。现有 SDK 已带运行库源码；配置版本号不等于重新核对过所有 SDK 厂商补丁，后续完整依赖锁需覆盖这些输入。

首轮 `cxx-probe-20260910` 真实编译在 libc++ thread.cpp 失败：要求 `CONFIG_TLS_TASK_NELEM > 0`。保留独立配置与 `evidence/build/cxx-probe-20260910/build-failed.log`，没有通过伪造 task_tls 接口绕过。第二轮 `cxx-tls-20260910` 补齐任务级 TLS 后完成 ARM64 编译链接。

第二轮镜像 SHA256：`8561f8ac9cd974d832f6f04dd813ab72558b25071405ab8565780f4454e9e8cd`。ELF entry `0x40400000`，加载内存5488640字节，现有6MiB保留边界检查通过。源码/产物哈希见 `evidence/build/cxx-tls-20260910/verification.json`，检查工具 `tools/verify_cxx_tls_image.py`。构建和原版本证据不覆盖。

真机结果以 `evidence/cxx-tls-20260910/runtime.json` 为准；文件尚不存在时表示未完成验收，不能以编译通过代替。加载使用 RAM 命令及逐块/整块 CRC，无 eMMC/STM32 刷写。

并行 llama B0 已交付固定提交 `74d4f5b041ad837153b0e90fc864b8290e01d8d5` 的主机 CPU 静态库及真实张量图探针，65份交付哈希由主任务核对，见 `evidence/voice-deliveries-review-20260910/llama-b0-review.json`。它没有权重或语言模型推理。下一步依赖包括：真实 NuttX 核心链接、线程池失败清理、CPU亲和性、模型大文件只读路径以及显式模型内存池分配域。当前普通 malloc 尚不能使用整个1GiB模型池。

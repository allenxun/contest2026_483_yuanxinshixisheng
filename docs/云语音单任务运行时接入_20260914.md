# 云语音单任务运行时接入（2026-09-14）

## 已完成与边界

新增 `app/k7agent/cloud/include/cloud_speech_runtime_owner.h` 和对应源文件。
一个 owner 持有一个 orchestrator 和 radio bridge；不分配堆、不创建任务或
定时器、不保留密钥、不发云请求。此阶段是可测试的任务生命周期核心，
尚未加入 CMake/Kconfig、SDK 同步、ARM64 构建或板端启动流程。

单独执行 `tests/k7cloud/run_runtime_owner_tests.ps1` 可在 GCC C11 严格警告下
跑 O0/O2；两档各 7 组通过。包括初次采样失败、两个无线门禁、断网、
漏采整个重连区间、取消再启动的代际防回退、提示资源失败、采样中重入和
同步请求忙状态。所有测试使用假的回调，实际云调用次数为零。

## 所有权与接入次序

1. 在唯一云任务里初始化 owner，传入长期有效的 speech ops、adapter、
   WAV/PCM scratch 和 radio 只读采样回调。初始化只用于新对象；不能通过
   重复初始化绕过 busy 或代际检查。所有对象和缓冲区要活得比任务更久。
2. radio 回调从 `k7radio_get_link_snapshot()` 复制 generation、Wi-Fi、
   IPv4 状态和地址，失败返回非零；不可把旧快照冒充成功新采样。
3. `cloud_speech_runtime_owner_start()` 关闭旧门禁并立即采样一次。
   初次错误返回给调用方，轮询生命周期仍处于运行状态，可以下轮重试。
4. 所有后续 `poll()` 都在同一任务进行；采样错误、桥接校验失败或本地
   提示播放失败均清掉八项门禁。正常无线快照最多打开 Wi-Fi/IPv4 两项。
5. 独立平台验证完成后，拥有者任务可对 `owner.speech` 调用现有
   `cloud_speech_set_platform_readiness()`。owner 自己不会宣布 DNS、熵、
   时间、CA、TCP 或 API 就绪。证据必须属于当前 radio generation；把
   异步旧连接的检查结果应用到新连接前，必须先比较 generation。
6. `cancel()` 停止后续轮询并清空所有门禁，可以重复调用。再次 start
   保留 generation 高水位，且六个非无线门禁必须重新检查。

任务外的无线事件应投递给任务或通过权威 snapshot 观察。此 API 没有
跨线程锁，不能从无线中断或另一个线程直接修改 owner。回调期间递归调用
start/poll/cancel 会返回 EBUSY。同步 speech 请求 busy 时也返回 EBUSY；
必须先由传输拥有者取消 socket、等待同步调用退出，再执行 cancel。
这不是已实现的异步 HTTP 取消机制。当前批处理 ASR/TTS 也不是流式 API。

## 实际 adapter 仍缺什么

当前 `k7cloud speech-status` 是离线链接诊断：传给 orchestrator 的
`ops_arg` 为 NULL，WAV scratch 仅 46 字节，PCM scratch 仅 1 帧。
它没有创建可用于真实播放或云请求的 runtime，不能把 linked 当作 ready。

正式接入 `cloud_speech_mimo_adapter` 必须提供：

- `network_connected_pcm16` 和 `network_connected_frames`：长期有效、
  已校验的 16 kHz 单声道 S16 本地“联网成功”男声资源。资源不存在时
  adapter 的 fixed_prompt 会失败，owner 返回 EPLAY 并关闭门禁。
- `mimo`：经过区域端点配置、DNS/TLS/证书和资源检查的 client；不能传 NULL。
- 足以容纳约定最长录音和 TTS 返回音频的 WAV/PCM 缓冲区，设置明确上限；
  诊断用 46 字节/1 帧不能用于产品运行。
- 唯一任务的固定频率轮询和所有权，平台验证结果的 generation 关联，
  bounded TCP 的真正取消与超时处理。

“联网成功”提示只代表 WPA2/DHCP 已成立；即使提示播放成功，也不能据此
宣布互联网、MiMo 权限或流式语音验收通过。后续真机验收仍需要 BLE 手动
密码配网回包、实际提示播放、六项独立门禁、云 ASR/TTS 和断网清门证据。

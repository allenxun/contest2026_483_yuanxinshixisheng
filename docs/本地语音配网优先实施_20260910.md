# 本地语音配网优先实施

用户确认顺序：唤醒 → 扫描网络 → 选择网络 → 输入密码 → 请求连接。取得真实网络连接后，再接小米云端语音/大模型接口。本地 llama.cpp/Qwen 不再是近期配网交付的前置条件；已有 CPU、模型池和存储成果保留。ASR/TTS 本地运行仍需要对应库、模型文件及资源验证，不能把“不需要本地大语言模型”误写成“不需要本地语音模型”。

## 本轮正式变更

从已核对交付哈希的 VoiceLink 候选迁入 `app/voicelink` 六份核心/解析器源码。未复制旧同步 WAPI 平台文件，没有接入模拟成功后端。正式差异：

- 扫描改为 `beginScan/pollScan/cancelScan`，保持控制流程可轮询和取消；30秒请求期限、唯一事务号、Ready结果最多64项。
- 接受扫描与返回列表分开；旧事务列表不采用，超时优先于同次到达的Ready，忙/不支持不会伪装成空列表，也不会要求断开已有网络。
- 成功列表按既有规则筛选和排序，最多播报5个网络；按编号选择。密码继续逐字符本地解析，允许删除、清空、切换大小写和取消；不回读完整密码。
- 连接仍按异步状态处理，只有匹配事务的有效IPv4成功事件可触发完成播报。网络不支持/消失后改为返回选网，修正原来仍停留密码输入的矛盾。

正式路径 O0/O2 各14个完整文字流程通过，包含忙/不支持后的重新唤醒。最新报告：`evidence/voicelink-core-integration-20260910/run-20260910T093758481394Z/result.json`。输入是识别后的文字，网络/AP/IP与声音端口都是明确的模拟；这些结果不证明实际录音、语音识别或真实语音配网通过。早先7场景及中间14场景版本报告保留。

## 仍需完成的设备端步骤

1. **无线服务统一仲裁。** 现有dispatcher只有连接请求，没有扫描API；真实扫描同步阻塞，在线实际返回-EBUSY。需同一服务接管BLE和语音扫描/连接，扫描租约直到STOP/CLOSE及回调退出确认才释放。不能让新语音端直接操作旧BLE扫描全局表。
2. **板载音频。** 用户已确认MIC/喇叭接线。I2C3时钟分频、codec配置与SAI1候选分开评审，先确认实际控制总线，再做低音量短播放和短录音；尚未启用实板音频。
3. **本地ASR/TTS。** 锁定实际ARM64运行库、模型文件路径和采样格式，先WAV推理再实时音频。只读FAT已独立编译通过但未上板，它仍可服务语音模型存储。
4. **真实全流程。** 唤醒、扫描真实列表、选网、密码、WPA2/DHCP、成功/失败播报，保存事务与不含密码的日志；与BLE同时使用时验证互斥和取消行为。
5. **云端。** DNS/HTTPS/实际小米接口与鉴权验证之后，再接自由口语和工具调用。初始配网不能依赖尚不可达的云服务。

## 并行交付边界

I2C3时钟纯函数候选由A提供；codec录音审查由B提供；扫描契约与精确接入点由C提供。均只在各自隔离目录，主会话统一集成。codec仍NOT_READY，扫描方案目前只有声明，没有虚构实现。接线不再重复询问。

本轮没有操作COM8、蓝牙、SDK或运行固件，没有刷eMMC/STM32或启动云台。当前运行镜像状态沿用最近USB只读版本的实测快照，不把它称为本轮重新验证。统一日志归属 `logs/maomaojiang01/`，以最新官方校验报告为准。

## 源码核对

当前CONFIG_RAM_START=0x40400000、CONFIG_RAM_SIZE=132120576、CONFIG_MM_REGIONS=1，MMU中的DRAM0_S0也只映射该范围。board/kickpi_k7/README.md记录DTB位于0x48300000，OP-TEE/固件保留间隙0x48400000–0x49400000；仍需用当前bootloader与DTB复核，不能把文档当作完整DDR可用区表。

无线固件在0x50000000–0x50200000单独只读映射，应用仍直接读取该范围；RAM加载工具还使用0x51000000快照。因此扩大单个连续heap会与既有地址约定冲突。rk3576_usbhost.c的DMA地址范围检查也依赖当前RAM_START/SIZE，新增多内存区需同步调整，核实外设DMA寻址宽度与缓存一致性。

当前CONFIG_MMCSD未启用，FAT/LittleFS等也未启用；未在统一RK3576端口文件中发现已集成eMMC块驱动。U-Boot能够从eMMC启动不代表NuttX已经能读写模型文件。

## 实施顺序与验收

1. 取得实板U-Boot DRAM bank、当前DTB memory/reserved-memory及固件保留表，建立64位地址区间清单。读取现有GPT/分区和容量，保存校验；不格式化、不覆盖Android/引导分区。读取行为与后续写入分开。
2. 保持当前启动窗口和关键保留区，按经过核实的可用DDR bank增加MMU映射与独立heap区；先纳入一段连续可用区，目标逐步扩展到全部可安全交给OS的DDR。不能在尚未确认地址前指定512MiB/1GiB区域或跨过4GiB物理地址边界。
3. 在明确划归测试的新增内存中做模式/边界/分配释放验证；检查地址截断、缓存与DMA，并回归Wi-Fi/BLE、USB视觉、NPU缓冲。保留区不参与内存测试。板子4GB不意味着free命令能显示完整4GB，需扣除固件、内核和专用缓冲。
4. 接入RK3576 eMMC控制器、块设备、分区解析和所需文件系统；先只读验证多位置内容一致性。形成可审阅的数据分区使用方案，只有具体写入范围得到授权后再进行写入/断电一致性测试，不更改既有禁止刷写约束。
5. 模型、词表放eMMC的受管数据目录；配置、照片、日志使用容量/轮转规则。仅在运行时将模型和中间张量放DDR，不把eMMC容量视为RAM，也不把全部浮点和INT8模型同时加载。模型峰值内存实测后再确定预算。
6. 形成持久启动方案，让断电后自动启动同一VelaVision固件和无线服务；单独审阅启动项/分区修改后执行。当前RAM加载可继续用于调试，不能作为持久启动完成证据。

## 资源用途

DDR：系统堆、Wi-Fi/BLE缓冲、USB图像、语音推理工作区、NPU DMA与模型运行内存；根据实际使用量隔离/预留，不要求无意义占满。
eMMC：固件部署、语音模型及词表、业务配置、照片和轮转日志。保留必要恢复能力，不将32GB全部格式化成单分区。

VoiceLink接入顺序更新为“DDR/模型存储基础 + 音频驱动 → ASR/TTS → 共享Wi-Fi服务 → Agent任务入口”。目前没有证据表明4GB物理内存本身不足；主要问题是BSP资源尚未接全、推理库与音频后端尚待移植。

本轮为源码评估与计划更新，没有修改固件、重启设备、改写eMMC或声明扩容已经完成。

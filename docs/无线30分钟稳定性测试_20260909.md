# 无线 30 分钟稳定性测试

用户要求先完成稳定性测试，再推进 AI Agent 部署。本轮保持当前固件，不重启、不刷写、不启动云台，也不通过自动重新连接掩盖断开。

## 固件与测试条件

- RAM 固件：`wifi-amsdu-index-20260909`。
- SHA-256：`85fb84d34a7dbc74469b91c501b3e289791a1b99636829690d3cc6210e688dfe`。
- Wi-Fi：原生 `wlan0`，Lansee，IP `10.3.0.214`，网关 `10.3.0.1`。
- BLE：手机调试器保持加密连接；起始连接数/断开数以每次测试基线为准。请将调试器保留前台，避免把手机 App 的后台行为混入设备端保持测试。
- 范围：网关通信与 BLE 连接保持，不包含 BLE 业务吞吐、互联网、iOS、强制断线重连或保证发生的 AP 重密钥。

## 测试方法和判定

`tools/run_wireless_stability.py` 独占 COM8，最多等待 5 分钟建立基线；手机已连接、已加密且 Wi-Fi 在线后开始完整 1,800 秒计时。每分钟 Ping 50 次，完成后读取 BLE、Wi-Fi 和堆内存状态，余下时间持续收集限定的状态日志。

通过要求：完成 30 个周期和至少 1,800 秒；1,500 次网关 Ping 全部收到；BLE 连接/断开计数不变化且加密保持；Wi-Fi IP 状态正常；无命令超时或采集故障。丢包保留并继续统计，连接或加密状态改变则停止本次保持验收并保存失败。内存记录用于观察趋势，不以一次波动推断泄漏。

只保存限定的状态字段，不记录通信载荷或密码。没有启动持续 BLE 数据发送，因此不能将结果写成“双向大流量业务稳定性通过”。

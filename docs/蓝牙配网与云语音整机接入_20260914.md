# 蓝牙配网与云语音整机接入（2026-09-14）

## 当前产品流程

本轮已按产品决定取消“语音输入 Wi-Fi 密码”。整机流程固定为：

1. 手机/前端通过加密 BLE 连接 K7。
2. K7 扫描 Wi-Fi，前端展示列表；用户选择 SSID 并在前端输入密码。
3. 前端调用已有 `connectWifi()`；K7 完成 WPA2 和 DHCP 后，通过 BLE 返回 `wifi_connected:true` 与真实 IPv4。
4. K7 立即播放板内固定男声提示“联网成功”。这条提示不依赖互联网或云服务。
5. K7 重新检查本次链路的 DNS、熵源、可信时间、CA、TCP 和 API 配置；全部通过后才进入 `cloud_ready`。
6. 联网后的录音调用 `mimo-v2.5-asr`，播报调用 `mimo-v2.5-tts`。当前实现是有界批式 HTTP 候选，流式版本仍是后续工作。
7. K7 用设备会话和心跳向业务后端报告在线；APP 读取云台状态，只在 `connectionStatus=online` 且 `isStale=false` 时显示“云端已连接”。

`wifi_connected` 只证明 K7 取得局域网地址；`internet_ready`、业务后端在线投影和 `cloud_ready` 必须分开显示。任何 Wi-Fi/IPv4 失效都会清空旧链路的 DNS/TLS/API 门禁，重连后重新检查，不能沿用旧结果。

主机/后端语音桥候选：

- `host/cloud_speech_bridge/bridge.py`

最小接口为：

| Method | Path | 成功语义 |
| --- | --- | --- |
| `GET` | `/health` | `ready/asr/tts` 均为布尔值 |
| `POST` | `/v1/asr` | 输入 16 kHz mono PCM16LE WAV，返回 `{"text":"..."}` |
| `POST` | `/v1/tts` | 输入文字和可选音色，返回 16 kHz mono PCM16LE WAV |

开发语音桥固定监听 `127.0.0.1`，适合虚拟机界面或本机进程联调。正式后端应在受控 HTTPS 服务内实现同一合同并持有 MiMo 账户密钥；前端和固件不保存该密钥。

板端云语音候选：

- `app/k7agent/cloud/src/k7cloud_main.c`
- `app/k7agent/cloud/include/cloud_speech_orchestrator.h`
- `app/k7agent/cloud/src/cloud_speech_orchestrator.c`
- `app/k7agent/cloud/include/cloud_speech_mimo_adapter.h`
- `app/k7agent/cloud/src/cloud_speech_mimo_adapter.c`
- `board/kickpi_k7/configs/velavision_cloud_speech_local/`

板端 ASR 接收裸 PCM16LE 或 WAV，但两者都必须是 16 kHz、单声道、16 bit；裸 PCM 会先包装成 WAV。MiMo TTS 的 16/24 kHz、单声道、16 bit WAV 会经过严格 RIFF/fmt/data 校验，24 kHz 批式转换到 16 kHz 后交给 `k7sound_speak_mono16()`。当前简单转换用于功能联调，高音质和低延迟版本仍需带低通的流式重采样。

独立 compile-only 配置已完成 ARM64 整包构建，离线 CLI 提供 `status`、`mimo-profile` 和 `speech-status` 三个诊断入口。它们只验证链接、profile 和闭门状态，不接收 Token、不发网络请求。真实 radio/DHCP 事件、熵源、可信时间、CA、非阻塞 TCP、API readiness 和运行时 Token 仍需由 owning cloud task 接入。

其后的默认关闭增量新增 `k7radio_get_link_snapshot()` 和 `cloud_speech_radio_bridge`：以锁保护的 generation 快照把真实 DHCP-backed Wi-Fi/IPv4 两门送入云语音，断链、旧代、同代矛盾或非法 IPv4 都 fail closed。O0/O2 各新增 6 组 radio bridge 测试并通过；该增量尚未重新做 ARM64 整包构建或上板，其他六门仍保持关闭。

## 给后端同事的音频答案

- K7 → 后端批量 ASR：**WAV，内部 PCM16LE，16 kHz，mono**。
- K7 → 后端流式 ASR：**raw PCM16LE，16 kHz，mono，20 ms/640 字节一包**；流元数据只发一次，每片带序号/时间戳/结束标记，不给每片重复 WAV 头。
- 后端 → K7 TTS：后端最好把 MiMo 的 24 kHz mono S16 WAV 解码并转换为 **16 kHz mono PCM16LE**；批式可返回 WAV，流式为 20 ms/640 字节一包。

# 音频滤波与夜间验证

当前独立固件为 `audio-filter-20260910`，RAM加载SHA256：
`8c8f46b4a354be34e6ff8d3d430cb81f70d583a8a0f929aeed0047ae5f1585fc`。
源码和构建见 `evidence/build/audio-filter-20260910/verification.json`。

新增独立逐声道MA4及MA4＋80Hz高通回放组件，不混合左右声道、不删除原始帧、不归一化。原始采集与普通replay保持原路径，单独输出缓冲占384KB。对应显式命令为 `k7sound replay-ma4-max` 与 `k7sound replay-hp-max`；它们都使用最大硬件输出，只供短时对照，不应循环播放。频率含义基于名义16kHz；当前原始采样有效性仍未通过。

纯C候选O0/O2各480061检查通过，正式ARM64编译、异常表、ELF/raw门禁通过，镜像运行内存7299072字节、8MiB门禁剩余1089536字节。板端短采集3200对（200ms）及一次MA4回放成功，饱和0，传输、停止、I2C和时钟恢复均返回0，功放低。HP80尚未板测。原始dump及命令证据见 `evidence/audio-filter-20260910/runtime-results.json`。

这次没有人工说话或实听，因此不构成音质验收。此前用户对PGA24录音的最终反馈是“人声更大，但杂声仍明显”。同一段PGA24录音由正式C组件产生两种派生WAV，48000帧完整保留、饱和0；Windows现有ASR分别处理原始/MA4/MA4＋高通，仍有识别偏差，不能据此宣称唤醒或语音配网可用。结果位于 `pga24-host-comparison/` 与 `pga24-host-asr/`。

每四帧三帧零的根因仍在定位。滤波不是采样修复，未开RDE或DMA，未改采样时钟或输入路由。后续通过独立数字路径诊断排查，继续共享无线事务接入；无线在线状态须以同镜像恢复测试为准。

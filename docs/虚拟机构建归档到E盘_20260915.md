# 旧构建转存 E 盘

用户要求将程序文件放到 Windows 磁盘，缓解 Ubuntu 空间不足。主项目源码原本已位于 E:\openvela\VelaVision；本次处理的是虚拟机中被替代的完整构建目录，不迁走正在使用的SDK或源码。

操作前 Ubuntu 剩余约9.2GiB，cmake_out占23GiB。归档目标为 E:\openvela\VelaVision\evidence\vm-build-archive-20260915T062136Z。

tools/archive_superseded_builds.py 逐个处理18个明确选定的旧目录：

1. 确认没有cmake/ninja/编译进程，检查源路径位于指定cmake_out内，生成所有普通文件SHA256及符号链接目标清单。
2. 从虚拟机流式压缩写入E盘，不在虚拟机另建临时压缩包。
3. 在E盘逐个读取归档成员并对照原清单，记录压缩包SHA256。
4. 再核对虚拟机源目录内容未改变、没有编译进程，才删除该可恢复目录。

保留 vision_ble_coexist、camera_reconnect、native_photo_prompts、tts_max、wifi_arp 五个构建；全部SDK、主项目源码、独立证据日志和私密配置均保留。每个归档旁的JSON记录verified及source_removed，部分完成时以这些文件为准，不将计划视为已完成。

归档包含完整构建树，不只固件BIN，包括对象文件、ELF、符号表、CMake配置及原有符号链接。恢复时应回到清单中的原Ubuntu路径，先校验归档哈希，确保目标目录没有现有改动，不能直接覆盖。默认保留当前整合候选与必要回退版，后续已替代的大构建及时按同样流程归档，避免不断叠加。

当前板子已为蓝牙/视觉共存修复进入Fastboot，待OTG接入；本次磁盘整理没有再次重启板子或写入eMMC。

## 完成结果

18份旧构建全部完成完整归档、逐文件SHA256校验及源目录清理。Ubuntu可用空间从约9.2GiB恢复至27.682GiB。第二批6份位于evidence/vm-build-archive-20260915T063621Z；第一批12份仍在前述目录。汇总见evidence/vm-space-recovery-20260915.json。

中间遇到一个未完成构建缺少ELF/BIN，脚本保护性停止且保留原目录。核实为有效CMake构建树后，按完整原始内容归档再清理，并记录final_artifacts_present=false，不宣称其编译完成。另一次只读查询自动权限审核超时，重试成功，无遗留阻塞。

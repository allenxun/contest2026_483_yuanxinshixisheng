# 连续对话测试界面（2026-09-15）

Ubuntu 已打开“VelaVision · 连续语音对话测试”，默认三轮。仅打开窗口不录音，也不占串口；用户点击开始后，向已运行的 openvela 发送一次 chat-loop，录音、问答、播放及下一轮全部由板端循环控制。

每次听到短音后说一句约3秒的短问题。界面依次显示准备录音、录音结束/完成识别、等待回答/下载与播放，以及最终结果。SOUND cue日志在实际录音结束后才输出，因此界面不会把这条日志误标为“刚开始录音”。目前没有实时波形或逐字识别文本显示；等待/下载/播放合并显示，不声称有播放开始的精确回执。

停止按钮通过同一个串口拥有者发送 device-stop。只有收到板端loop_done才确认停止；未知状态禁用再次开始。读取异常后尽力发送停止并等确认，不把串口已释放当作板端已停止。关闭运行中的窗口先请求停止，不静默丢下任务。

源文件：host/voice/chat_panel.py、launch_chat_panel.py、test_chat_panel.py。
部署副本在Ubuntu统一项目的host/voice，截图及UI日志在evidence/chat-panel-20260915。8项测试覆盖结束条件、cue日志时序、取消/错误、串口释放、异常停止与缺少确认。实际截图已检查；尚未通过用户按钮操作/喇叭实听验收。

语音网关仍为PID47076，已配置明确的依赖超时/不可用语音提示，并记录error_notice，未自动重发问题。既有76项网关与整机测试通过；本轮没有更换固件或操作云台。后端同事正在修AI无回答问题，不能把错误提示当作正常聊天回答或完整闭环。

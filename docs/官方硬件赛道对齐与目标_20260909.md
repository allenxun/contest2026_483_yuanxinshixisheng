# VelaVision 与官方新硬件适配赛道对齐

核对日期：2026-09-09。项目：KICKPI K7 / RK3576 4+32GB，实板无线 VS6621SR80。以下是本地代码和已有证据的核对，不新增硬件验收，也不代表已提交赛事仓库。

## 定位与官方依据

建议作品定位：**VelaVision——面向视觉机器人的 RK3576/KICKPI K7 原生 openvela BSP、无线与视觉驱动适配及应用验证。**

官方把 KICKPI-K7 明列为待适配平台，vendor_rockchip 的 K7 页面也标记尚未适配。因此选板与本赛道匹配；这不能单独证明我们完成了全球首次移植。[官方硬件清单](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/hardware_porting/supported_hardware.md)、[K7 上游指引](https://github.com/open-vela/vendor_rockchip/blob/dev-ai-contest-2026/boards/rk3576/kickpi-k7/README_zh-cn.md)。

赛道核心是系统启动、基础外设、配置与适配源码交付；更多驱动、应用演示、专用硬件能力和复现质量可加强作品。指南推荐的 driver-workflow agent 用于开发驱动，并未要求机器人必须运行大模型 Agent。[赛道指南](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/hardware_porting/hardware_porting_track_guide.md)。

保留最终机器人目标，但把比赛基础交付与上层能力分开验收。不能因为 Agent 尚未部署而否定已完成的原生驱动工作，也不能因为单项驱动通过就写整机闭环完成。

## 提交结构需要补齐的地方

队伍作品走专属仓 fork/PR/合入；修改 NuttX 等公共仓时，应按公共仓单独 PR、由组委会审核的流程处理。获奖后的 vendor 上游贡献另行办理，不能把公共层修改全部延后。官方提交指南当前写明截止日为 9 月 20 日，提交时复核最新公告及权限。[参赛代码提交指南](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/code_submission_guide.md)。

本项目待办：

1. 明确 `port/new/nuttx`、`port/tracked/nuttx`、`patches` 中芯片/公共驱动改动的来源和目标仓。`linkfile` 当前只映射应用与板级目录，不会自动应用这些公共改动。
2. 核对当前 `nuttx/boards/arm64/rk3576/kickpi_k7` 与上游 `vendor_rockchip/boards/rk3576/kickpi-k7` 布局的迁移方式；先保持现有可构建路径，不能只改文件夹名就声称上游结构完成。
3. 固定 SDK 提交、编译器/依赖、补丁顺序、配置、固件哈希与 RAM 启动步骤，在干净目录完成一次真实复现。构建输出与原生运行证据分别保留。
4. 复核厂商无线固件、引入源码和模型的许可证、再分发范围与取得方式；不把 Android/Linux 参考包或本机私密配置当提交物。
5. 准备队伍仓可审阅改动，以及公共仓所需的独立补丁；远程提交另按用户授权执行。报告、视频、真机证据和 AI 日志同版本归档。

## 后续目标和次序

**第一阶段：收好当前硬件适配交付。** 修正文档中的旧 WPA/IP 状态，补复现流程和公共改动清单；无线补 BLE 长保持、反复连接与并发业务验证。每项记录时长、版本、输入、失败和真实结果。30 分钟的一次丢包原因尚未定位，不能归因为硬件故障或直接归因为重放过滤。

**第二阶段：完成前端正式配网。** 将已验证的原生认证/DHCP 接入 BLE 事务，补过程/成功/失败事件、错误码、事务 ID 和 IP。端到端通过后才把 `connect` 改为 true；现有“已收到”不能改写为“已联网”。

**第三阶段：接入最小机器人 Agent。** 位于 RK3576 应用层，拟为 `app/k7agent/`。先做“文字指令 → 模型任务理解 → 明确 Tool 调用 → 读取真实状态 → 回复”；再接单次拍照。已有 `config/agent-model.example.json` 只是配置模板，尚无运行时部署；模型服务/离线方案待定。云端方案还需 DNS/TLS/实际接口连通验证。Agent 不直接生成任意串口动作，STM32 保留实时执行职责。

**第四阶段：扩展完整视觉机器人。** 接完整 NPU 模型、仪器检测、连续任务与异常恢复，再接 ASR/语音交互、整机感知—决策—执行演示。保留已验收的人脸跟随和三视角拍照；联合动作测试单独安排。

这四阶段是项目实施建议，不是官方指定开发顺序。赛道提交成果应以实际已完成的硬件移植为基础，上层机器人目标分阶段迭代；当前不承诺在未确定模型、复现和验收条件下的完整交付日期。

## 本轮变更范围

本轮仅对齐官方资料、更新状态与计划、归集真实 AI 日志。无固件改动、无重新长测、无 eMMC/STM32 刷写、无云台动作、无远程提交。源码/日志历史对应仍见 [代码日志对应表](代码日志对应表.md)，最新日志数量及分日文件以 `logs/maomaojiang01/manifest.json` 为准。

# A72计算与无线并发验收

目的：上一版证明八核能够运行且CPU0上的无线可配网，但没有持续计算与无线通信重叠。本轮新增独立 `smp-load-20260910` 候选；保留此前镜像与验收，不覆盖旧结果。执行结果以同名 evidence 目录为准，本文测试设计本身不代表通过。

## 实现

`app/k7load` 为显式命令，一次RAM启动只允许执行一次。4个线程固定CPU4–7，每轮约2毫秒整数运算后休眠2毫秒，目标时长60秒。它不是满载、语音模型或NPU性能测试。普通服务默认CPU0；不初始化外设，不写存储，不调用云台。

运算为32位xorshift，固定种子0x12345678，每4096步期望0xf6e37410。volatile阻止编译器用常量替换实际计算。O0/O2主机各100批与参考值一致，证据 `evidence/k7load-host-20260910/result.json`。线程记录核编号错误、校验错误、休眠与时钟错误、批数、墙钟时长和计算段墙钟累计；后者不是精确CPU利用率。共享原子计数须与各线程批数总和一致。

main最多等待63秒，失败发stop，静态上下文保留，拒绝重跑；每线程也有单调时限和循环次数保护。脚本总观察66秒，超时保留失败，不自动重复启动。发生调度/内核故障时这些软件时限不等同硬件看门狗。

## 真机观察设计

1. 校验新构建源码/ELF/配置，RAM加载并核对8个IDLE及默认服务亲和性。
2. BLE客户端进行真实配网，收到IP后保持连接，每约5秒发送status；记录事务ID、IP和主机时间，不记录密码。
3. NSH后台运行45次网关ping，随后前台运行k7load，采集白名单诊断行与时间。只读状态收集不重复基础NPU、USB、云台或eMMC测试。
4. 检查每核真实时长、零错误、网关收发结果，并核对BLE状态回包确实落在LOAD开始与结束之间。仅“前后在线”不作为并发回包证据。
5. 测试结束后观察网络及BLE状态、堆和线程栈余量，再明确记录当前实际运行版本。短时通过不能覆盖历史reason8或长期稳定性缺项。

工具：`tools/check_compute_radio_overlap.py`、`tools/ble_load_monitor.py`。主机监控时间只用于相对事件重叠，不宣称与板端时钟同步。所有输出位于同仓，官方AI日志归属 `logs/maomaojiang01`。


实际增量：smp-load-20260910 RAM运行，四A72各60秒、1412766批零计算错误，ping45/45；时间重叠核对BLE回包11次、网关回复45次。A-MSDU快照2→5，不满足严格零接收异常，不能归因为计算负载或宣布长稳。首轮后台提示符采集失败未启动计算；第二轮修正主机采集后一次完成，全部记录保留。详见 evidence/smp-load-20260910/acceptance.json。

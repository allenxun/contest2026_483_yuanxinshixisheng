# 构建与集成说明

## 2026-09-09 无线认证与 IPv4 增量

当前无线增量使用 CMake/Ninja 构建入口。认证版为 `tools/build_wifi_auth.sh`；IPv4 版为 `tools/build_wifi_ip.sh`，独立配置 `board/kickpi_k7/configs/velavision_wifi_ip_local/defconfig`，生成目录 `cmake_out/velavision_wifi_ip_20260909`。此增量尚未验证旧 Makefile 构建路径。

WPA2 状态机的上游源码、原始许可证、来源哈希在 `app/k7radio/hostap/`，适配源文件由 `supplicant.cmake` 接入。IPv4 配置增加 Ethernet、UDP/TCP、ICMP、DHCP 和 IOB 队列资源，保留 BLE 配对修正。构建脚本先执行 SDK 哈希核对；`evidence/sync/` 只记录已明确生成的源码版本，不能作为构建或上板成功的证明。

每个版本的 `evidence/build/<版本>/verification.json` 保存编译、测试和源码/固件哈希；`evidence/<版本>/` 保存单独的设备结果。最新真实认证和 IP 状态见 [Wi-Fi 认证与 IP 接入](WiFi认证与IP接入_20260909.md)，下方为首次集成历史。

本次将现有应用、RK3576 芯片/板级、USB Host 和蓝牙公共层修改归入一个赛事 Git 工作区，并将视觉、云台、NPU 实验和无线应用编译到同一原生镜像。`legacy/` 和 `work-in-progress/` 一并管理，但不会因此自动进入板端运行链路。

SDK 基线：nuttx `e987a81c32cab008d1a8521669e5488d00271322`；apps `92cc8c56a4c9b780b38991401295179fa2461908`。取回文件来源和哈希见 `evidence/sdk-inventory.json`；旧交付、前端、STM32 导入记录见 `evidence/local-imports.json`。

新配置从 id36 无线配置派生，开启既有 JPEG/YuNet/跟随/拍照、NPU 诊断及固定矩阵实验。以 NSH 为入口，所有无线/视觉/NPU 命令均需明确调用。RAW NPU 仍为隔离诊断实验，不是正式模型运行时。

首轮编译发现蓝牙两个发送队列各有 16 项，而全局预分配消息只有 8 项；新配置将 `CONFIG_PREALLOC_MQ_MSGS` 调整为 40，满足两个队列并留出余量。编译检查保持开启，未屏蔽警告；旧 id36 配置未改。失败日志保留。

构建结果见 `evidence/build/integrated-build.json`。`k7host_main`、`gimbal_main`、`k7npu_main`、`k7radio_main` 均在 ELF 中。静态 DRAM 占用约 4,792 KB，配置内存 126 MiB；不能据此推定动态峰值或多任务稳定性。

## 后续统一开发流程

1. 在本仓 `app/`、`board/`、`port/`、`frontend/` 等目录修改代码。
2. 同步项目源码到 Ubuntu，完整 SDK 保持 `/home/swl/openvela`。
3. 只读检查：`python3 tools/sync_sdk.py --sdk /home/swl/openvela --check`。
4. 编译：`bash tools/build.sh /home/swl/openvela`。脚本遇到未知 SDK 改动会停止。
5. 固件、配置和源码哈希形成新版本，再做真机验证，分别记录编译通过、单模块通过、联合通过。
6. 更新同仓 `logs/maomaojiang01/`，提交前运行官方 `validate-log.py logs/`。

公共层修改通过 `port/tracked/` 和 `patches/` 保留，尚未官方合入。当前清单的 linkfile 和公共补丁需要按官方提交流程复核。异机 SDK 不符合固定基线时不得直接覆盖。

本次未启动集成固件、未重复旧硬件测试、未启动云台、未刷 eMMC/STM32、未提交远程。Android 对照镜像和 Wi-Fi 厂商固件未混入集成源代码。

# 音频零样本定位：2026-09-11

当前能录音并从板载喇叭回放，但人声伴随明显杂声，尚未达到语音配网验收条件。本记录区分诊断结果与声音质量修复。

## 已确认的事实

- 静音内部数字回环也出现周期性零样本，因此该现象不需要麦克风声学输入即可复现。
- RX 路由改为全部 SDI0 的单变量试验未消除原模式。
- 编号回环保留的 256 个原始字中有 194 个零、62 个不同且有效的源编号。数据在推进，不能解释成一个旧样本被反复读取。没有删除零值或通过归一化掩盖它们。
- 09:33，`audio-mmu-20260910` 在 RAM 启动，实际 BIN SHA256 为 `886137227992f07ff1a32ff3662d4de2c799d1baa6fa15238bbba75cfbed2638`。ELF、二进制布局、异常表和当前 SDK 输入哈希已核对。
- CPU0 两次寄存器快照一致，三次页表读取成功。SAI 地址 `0x2a610000` 的输出物理地址相同，MAIR 属性字节 `00`，Device-nGnRnE、identity、AF 均为 1。

这支持当前 EL1 页表属性正确；不独立证明 TLB、Stage2 或所有别名映射。没有以此宣称整个音频路径正确。

## 无线回归

09:34，同一 MMU 镜像经本地私密串口入口完成真实 WPA2/DHCP，获得 `10.3.0.214`。空 ARP 缓存起步网关 5 发 5 收；A-MSDU 1 组、2 子帧、0 拒收。BLE 服务注册，客户端未连接；本轮没有 GATT 成功结论，也不是长期稳定性验收。

## 下一项实验

独立 `audio-rx2-20260910` 只将 RXCR.CSR 从一路改为两路，保持 TX、时钟、双 slot、默认回环路由和编号源不变。固定收取 128 个 word-pair，比较取数时长及原始编号分布。两路模式下的 word-pair 不能直接称为物理双声道音频帧，也不能直接导出 WAV 评价音质。

实验保留原始数据和 CSR 修改前、运行中、恢复后的读回值。停止或恢复失败会保持失败状态，不继续普通录放音。功放保持关闭。

## 20:00 S16 与 RDE 对照

`audio-s16-20260911` 将 SAI 有效位宽和总线位宽改为 16 位，BCLK 为 512 kHz，其余采集路径保持不变。真机仍出现一个有效 packed word 后三个零的周期，3200 帧请求只得到 2399 帧并超时；位宽配置本身不是根因。实际 RAM 固件 BIN SHA256 为 `34972feb5a1b5f16c73efdeeec7c8ef2dc39a204dcaafec8d6027ed17cca270e`。

`audio-rde-20260911` 按 Linux 驱动的启动顺序设置 `DMACR.RDL=16` 和 `RDE=1`，结束时关闭 DMA request 并恢复寄存器。真机运行、停止、codec、平台、I2C 恢复均返回 0，但前 32 次 RXDR 读取仍是 FIFO0 两个有效字、FIFO1 至 FIFO3 六个零的循环；RDE/RDL 没有改变周期性零样本。实际 RAM 固件 BIN SHA256 为 `b2aac75a43de4217bb210a09c4bf07f2686f4be6e5f1a421eff258c24099f43e`，原始结果见 `work-in-progress/audio-rde-20260911/board-result.json`。

当前 `audio-rx4-20260911` 候选已完成主机 O0/O2 测试和 ARM64 增量编译，BIN SHA256 为 `dcc2f2423a89eeeb6b89c1d4cb34ba4aa11da840878b03aec7fc0f5fec01c2ba`。它依次检查 CSR=4 的默认接收路由与四 lane 全部映射到物理 SDI0 的路由；截至记录时尚未 RAM 启动，不能作为真机结论。

## 20:39 RX4 与 MONO 真机补充

`audio-rx4-20260911` 已 RAM 启动。CSR=4 默认路由的 3200 对采集约 33 ms，证明它改变了接收字吞吐，不能直接把每一对当成 16 kHz 帧。四路都映射到 SDI0 后，非零计数增加，但本轮无人声输入，原始值主要为 `-1/0`，不足以接受或拒绝实际语音质量。该模式的真机结果只证明四个 FIFO 均可由同一 SDI 输入填充。

`audio-mono-20260911` 设置 `MONO_CR` 的 RX mono slot0，并按每个输出帧读取一个 RXDR 字。3200 帧中左右镜像各有 800 个非零值，前 32 次读取仍按 FIFO0、FIFO1、FIFO2、FIFO3 轮转；MONO_CR 没有把 CPU 读口收缩成单一 FIFO。BIN SHA256 为 `4eabd6d71f7087893d018cb75b81565bd5fc149376b2c9724a3aa99d65c45244`，构建与原始串口证据见 `evidence/build/audio-mono-20260911/verification.json`。

基于两项真机结果，新增 `audio-grouped-20260911` 候选：CSR=4、四路映射 SDI0，每个 16 kHz 周期等待四个 FIFO 各至少一个条目，固定读取完整的 8 字轮转，仅保留第一个槽并将四份复制不一致计数作为门禁。O0/O2 主机模拟与旧 PIO 回归已通过；尚未交叉编译和上板，不能称作采集修复。

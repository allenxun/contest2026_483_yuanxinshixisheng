# 知识库语音聊天接续

目标链路：K7麦克风 → 阿里云流式ASR → 业务服务的知识库检索与对话模型 → 回答文本分句 → 云TTS → K7喇叭。ASR负责听写，TTS负责播音，知识库/对话模型负责回答。需要保留会话历史、支持取消旧请求，后续再做打断播报和持续监听。

## 请知识库服务方提供

1. 实际调用URL、HTTP方法、请求JSON和鉴权方式。
2. 已发布的工作流/应用ID，是否关联目标知识库。
3. 会话ID如何创建、后续轮次如何复用；设备与用户权限如何隔离。
4. 普通文本回答与流式回答格式，流结束和错误标记、超时、取消方式。
5. 一条不含个人资料的联调问题及预期知识库命中内容。

密钥保存在服务器端，前端和K7不保存厂商密钥。收到真实接口合同后再写适配器，不猜测调用路径。

## 建议接口合同（待后端确认，不是已上线接口）

可由业务后端提供一个POST聊天入口，输入 requestId、conversationId、text、设备会话；服务端从授权上下文确定知识库范围。不能由客户端任意指定其他用户的知识库。

响应建议SSE或WebSocket，事件包括 answer_delta（文本增量）、answer_done（本轮结束）、error（安全错误代码）。真实协议如果已存在，适配现有协议，不强制后端采用本建议。

ASR的partial仅用于字幕，同一句partial覆盖上一次快照；正式问答由完整一句final触发，并按句ID去重。回答积累到完整短句再送TTS，避免每个token调用一次；保留有界播放队列。新轮次/取消必须使旧回答和音频失效，不能让旧响应串入新对话。

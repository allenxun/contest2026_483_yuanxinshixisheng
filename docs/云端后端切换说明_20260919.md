# 云端后端切换说明

VelaVision 的三视图上传、任务轮询、brief 报告和报告讲解流现在可以指向云端部署，同时保留原有局域网开发链路。默认配置不变，未设置环境变量时仍使用 `host/whole_device/assessment-upload.dev.json` 中的 `http://10.3.3.170:18085`。

云端 Swagger：<https://eveaisia.com/openvela/swagger-ui/index.html>

## 云端运行

设备认证、上传、任务状态、报告和讲解流必须使用同一个后端地址和同一个云台 Bearer token。启动主机网关前设置：

```bash
export VELAVISION_BACKEND_BASE_URL=https://eveaisia.com/openvela
export VELAVISION_ASSESSMENT_CONFIG=host/whole_device/assessment-upload.cloud.json
```

Windows PowerShell 等价写法：

```powershell
$env:VELAVISION_BACKEND_BASE_URL = 'https://eveaisia.com/openvela'
$env:VELAVISION_ASSESSMENT_CONFIG = 'host/whole_device/assessment-upload.cloud.json'
```

也可以不设置环境变量，直接在原来的网关命令上追加（只传 `--backend-base-url` 时会沿用默认配置中的同意凭据引用）：

```bash
python -m host.streaming_asr.board_bridge --host 0.0.0.0 \\
  --assessment-auth private/gimbal-device-auth.json \\
  --backend-base-url https://eveaisia.com/openvela
```

私有认证文件不需要复制到项目，也不要把 credential、proof 或 session token 写入日志。

## 保留的原有功能

- 不设置上述变量时，局域网地址和原有上传协议保持不变。
- 摄像头接收、三视图顺序、JPEG 校验、幂等键、断线后的本地 spool 和任务回传均不改变。
- 上传成功后继续按 `queued/analyzing` 轮询；`needs_retake`、`failed`、`report_ready` 和 `TASK_REPLACED` 仍按原逻辑处理。
- `report_ready` 后使用返回的 `reportId` 请求 `skin-reports/{reportId}?view=brief`。
- 报告讲解 SSE 若返回当前后端的 `422 UNSUPPORTED_CONTRACT`，继续降级为真实 brief 报告播报，不把 mock 文案当验收结果。

地址解析会拒绝带 query 或 fragment 的配置，并在真实上传前检查登录地址和上传地址是否一致，避免“认证成功但图片传到另一套后端”的隐蔽错误。

## 当前边界

云端切换是主机后端地址和认证来源的配置变更，不会改变板端视觉、云台、人脸跟随、语音唤醒或三视图拍摄流程。首次切到云端必须重新拍一组三视图；旧局域网任务不能迁移到云端任务空间。实际云端上传和报告完成仍应以新的 `taskId`、`reportId` 和现场日志为准。

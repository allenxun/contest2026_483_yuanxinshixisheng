# 服务器配置接续

服务器 bool@10.3.3.170，SSH 22。原业务服务 18085 未修改。
原生 Python 3.12 venv：`/home/bool/velavision-speech/venv`。
发布目录：`/home/bool/velavision-speech/releases/20260915T034307Z`。
Docker Hub 超时，实际采用 systemd，不需要 Docker。

用户最终要求由后端配置密钥。此前获准传输的 .env 已删除；不再传用户密钥。
由后端在发布目录创建 `speech.env`，参考 `speech.env.example`，填入后端管理的阿里云配置并 `chmod 600 speech.env`。不要把真实内容写到聊天或日志。

```sh
cd /home/bool/velavision-speech/releases/20260915T034307Z
cp -n speech.env.example speech.env
chmod 600 speech.env
nano speech.env
sudo systemctl start velavision-speech velavision-speech-bridge
systemctl is-active velavision-speech velavision-speech-bridge
curl --fail http://127.0.0.1:8000/health
```

已设置开机启动。8000 仅服务器回环；流式路径 `/asr/stream`，批量 `/asr`，TTS `/tts`。
桥为 `10.3.3.170:8001`，systemd IP 限制只允许 K7 `10.3.0.214` 与回环。K7 DHCP 地址改变后须更新 bridge unit 的 IPAddressAllow 并 daemon-reload/restart，不能把地址变化误判成模型故障。
默认没有 echo-test；普通 TTS 播请求文字。真实阿里云 ASR/TTS 及 K7 端到端验收仍需密钥配置后进行；health 不代表云端推理通过。

K7 目前未切换服务器地址；现有电脑服务保持，避免中断用户调试。

实测：两项systemd服务均active，/health返回200及status=ok，127.0.0.1:8000与10.3.3.170:8001监听正确。检查使用空配置、未调用云端。随后两项服务已停止，speech.env已删除，开机启动配置保留。

# 微晶：APP 与云台控制、人脸核验及完成次数

本项目护理硬件统一称为“微晶”，始终是同一种设备，不再区分两类硬件。微晶可由 APP 或云台直接连接并控制。当前文档包含 Markdown、draw.io 和配套网页；网页展示所需的通信图资源随文档保存。

## 一、本轮确定的规则

| 事项 | 当前规则 |
| --- | --- |
| 云台开始护理 | 开始前采集当前人脸，调用云端匹配；确认与方案所属成员相同后，才获取并执行本人方案 |
| 云台离线执行 | 完成开始前核验后，只要本轮人脸追踪持续未丢失，就可以离线继续，无需每个执行动作都联网核验 |
| 云台追丢或换人 | 云台不认识具体是谁，只能判断追踪连续性。追丢、重新捕获或出现新追踪目标后，原连续性失效，暂停或停止并重新联网核验 |
| 无法重新联网 | 保持暂停或停止，不因重新看到一张脸就恢复原方案 |
| 方案完成目标 | 生成并返回方案时估算预计完成次数 N；记录实际累计完成次数 K，达到 N 标记该方案完成 |
| APP 查看 | 用户在 APP 获取人脸并发起授权，后端匹配成员后建立本人资料的查看权限 |
| APP 护理控制 | APP 可直接连接微晶，获取本人适配方案后开始、暂停或结束护理；此能力属于当前范围 |
| 控制端互斥 | 同一设备、同一次护理仅由 APP 或云台中的一端控制，不能并行控制 |
| APP 拍照测肤 | 作为未来能力，用虚线标记为非 MVP；与用于查看授权的人脸采集是两件事 |
| 实施细节 | 简版字段、协议、设备配对细节、心跳与重试等具体参数先不展开 |

“允许离线”不等于可以对未经核验的新使用者直接离线启动。每次新的护理会话开始前仍需核验；同一连续护理会话内不必对每次动作反复联网。

## 二、角色与边界

- **APP 使用者**：MVP 内通过 APP 人脸授权查看本人完整版报告、方案、云台状态及护理记录，也可辅助云台配网。APP 可直接连接微晶，开始、暂停或结束护理，并记录实际完成量。未来可使用 APP 拍照测肤，本版只用虚线预留。
- **云台使用者**：通过云台发起测肤和护理，听取简版结果；护理开始前接受云端人脸核验。
- **云台设备**：负责语音、拍照、追踪、获取数据、直接控制已连接微晶和记录实际完成量。它不识别具体身份，只维护追踪连续性。
- **后端系统**：是用例图的系统边界，负责身份匹配、查看与执行权限检查、设备能力、报告与方案、执行登记、控制端归属和进度记录。后端不转发开始、暂停、结束等本地控制指令。
- **算法服务**：提供测肤分析和人脸匹配，分别支持自动归档、APP 查看授权及护理开始前核验。
- **大模型服务**：按报告与护理规则生成候选方案及预计完成次数，后端校验后保存。
- **微晶**：本项目统一的护理硬件，可连接 APP 或云台，由本次选定的控制端直接操作。同一次执行仍只有一个控制端。

APP 使用者与云台使用者可以是同一个人，但仍是不同操作角色。没有增加云台上的手动选择姓名或确认成员身份步骤。

## 三、APP 人脸授权与查看

1. APP 使用者在 APP 获取人脸，发起本人资料查看授权。
2. 后端请求人脸匹配，关联已有成员档案。
3. 可靠匹配成功后，建立当前 APP 账号对该成员报告、方案与护理记录的查看权限。
4. 未匹配到或结果不确定，不授予其他成员的查看权限，提示重试或暂无对应资料。
5. 后续查询均检查这份成员访问关系，返回完整版内容。

历史查看授权不能代替本次执行检查。APP 控制微晶时，还需核对当前使用者与方案成员、目标设备能力和可执行状态；校验通过后才能开始。APP 拍照测肤是另一项未来功能，尚不纳入 MVP，也不在本轮定义其采集规则。

## 四、云台护理前核验与连续追踪

### 开始前

云台使用者提出护理需求 → 云台采集当前人脸并建立追踪 → 后端请求云端匹配 → 核对为当前任务方案所属成员 → 返回该方案与后端已保存的 N/K → 云台确认本次核验响应仍对应当前追踪 → 本地开始执行。

核验期间若已经追丢，不能拿刚返回的旧核验结果直接开始。若云端判定换成另一成员，不继续原成员方案，应取得新成员自己的报告和方案；其尚无报告时先测肤。

### 开始后

- 追踪持续：按同一连续护理会话处理，可离线执行并累计实际完成量，不重复联网核验。
- 追踪丢失：暂停或停止执行，使原身份连续性失效。
- 重新看到人脸：不自动视为原成员，必须重新调用云端匹配。
- 无网络：等待联网重验，不能恢复原方案。
- 重验为同一成员：保留原方案版本和已完成量，在条件满足时继续，不能重复计算已经完成的部分。
- 重验为其他成员：切换到该成员自己的方案与进度，不能继承前一个人的完成量。

这里用追踪连续性维持一次核验后的使用上下文，不把端侧追踪当作身份识别。

## 五、预计次数与完成判定

1. 方案生成时估算预计完成次数 N，并与成员和方案版本一起保存。
2. 当前控制端（APP 或云台）获取方案时，一起取得 N 及已有进度；APP 完整版和云台简版使用相同的目标与状态。
3. 当前控制端只累计实际有效完成量 K。方案下载、启动请求、重复领取及重复上报不算完成次数。
4. K 未达到 N：保留剩余次数，由当前控制端按本次执行上下文继续。云台路径仍受人脸追踪连续性约束；不假定 APP 具有同等追踪能力。
5. K 达到 N：标记当前方案完成，不因重连、重新获取或重复上报再次执行已完成部分。
6. 离线时保存实际进度；恢复联网后去重同步，后端更新总进度，APP 可查看预计、已完成、剩余次数和完成状态。
7. 中断不能直接按整项完成计数，只保留实际有效完成量。

本轮不细化“一次”对应的具体设备动作或计量单位，也不把次数强行等同于下载次数、启动次数或护理会话数量。N 是方案的完成目标；计数达到 N 不等于已经验证皮肤效果。

## 六、统一数据与两端视图

后端只维护同一套报告、方案和版本：APP 获得完整展示内容，云台获得简短交互内容及执行必需的数据。云台简化展示不能丢失执行所需参数和限制。

报告生成后即可查询，不需要等待护理方案。方案尚未就绪、身份未核验或当前方案已完成时，不应进入执行。成员、方案版本与实际进度保持对应，换人不混用。

## 七、当前范围与暂不展开项

- MVP／当前范围：云台拍照测肤、自动归档、APP 人脸授权查看、APP 连接并控制微晶、云台护理、两端视图、执行前云端核验、云台连续追踪下离线执行、方案预计次数与进度同步。
- 非 MVP（虚线）：APP 拍照测肤。
- 暂不展开：具体字段及播报长度、微晶协议与能力上报格式、配对机制、具体暂停实现、网络检测参数、重试参数、人脸算法阈值及保留策略。

暂停或停止的具体设备指令属于实施层；业务规则已经确定为“追丢后不得未经重新核验继续执行”。

## 八、APP 微晶控制流程

1. APP 使用者选择并连接微晶，APP 获取设备能力和实际状态，并上报后端。
2. 使用者选择本人方案及目标设备，发起开始护理。APP 采集当前人脸，后端调用云端匹配，核对为方案所属成员。
3. 后端检查方案是否适配该设备、设备是否正由其他执行占用以及操作请求是否重复。校验通过后登记本次执行，固定控制端为 APP，返回方案版本、预计次数 N 和已有实际进度。
4. APP 保存执行上下文，再次确认本地设备就绪，仅对首次有效执行发送开始操作。
5. 微晶反馈实际状态；APP 展示进度，记录完成次数并向后端同步。指令已发送不代表执行已成功，失联时不能显示虚假的完成状态。
6. 暂停和结束由 APP 直接对本次连接的微晶操作，不经后端转发，也不等待后端响应。设备不支持暂停时明确说明，可使用其支持的停止操作。
7. APP 保存并上报实际记录，后端与云台路径共用同一方案的累计进度。断网时可缓存记录，恢复后去重同步，不自动重新开始护理。

### 控制端与进度

- 同一台微晶、同一次执行只有一个控制端。APP 与云台不能同时发送相互冲突的指令。
- 切换控制端前，结束原执行并确认设备已停止，再由新控制端核验、取得适配方案并创建新的执行上下文。旧执行状态未知时不能直接抢占。
- 记录的成员、设备、方案版本与控制端需对应；重复同步不重复计数，切换控制端不清空已经完成的有效进度。
- 控制端变化不一定需要更换方案；目标微晶变化则必须重新检查适配性，必要时重新生成方案，不能直接套用不适配的参数。
- 后端支持合法 APP 和云台的执行登记与记录同步，但不恢复旧版“APP 请求后端向云台转发护理指令”的结构。

### APP 与云台的身份连续性区别

APP 开始前也做当前人脸核验，但不默认 APP 具备云台的持续追踪能力。已确定的“追踪持续可离线执行、追丢后重验”规则只适用于云台。APP 运行中身份连续性、离线运行和后台运行的具体策略待实施阶段确定，不在此次扩展中擅自套用云台规则；本地停止途径必须保留。

## 用例名称说明

## 十、当前简化约定与 APP 撤销关联（本轮补充）

本节记录用户最新确认；与前文关于方案版本、适配范围或授权期限的描述不一致时，以本节为准。

- “云台”负责拍照、人脸追踪、联网与心跳，可直接控制微晶；“微晶”是实际执行护理的硬件。认证/心跳/离线通知明确指云台，护理连接/占用/完成反馈明确指微晶。
- APP 查看授权永久有效，直至账号主动在 APP 撤销该人脸对应成员的查看关联。撤销后该账号不能再查询该成员的报告、方案和护理记录；只撤销关联，不删除成员、人脸档案或护理数据。旧登录状态或重复授权请求不得绕过撤销。
- 新增对外接口 M1-A03：`DELETE /api/v1/me/member-access-grants/{grantId}`。对应 APP 主动撤销关联，是原流程图 05 页的新增补充，现已补入原流程图 05 页的 revoke_select/revoke_grant/revoke_ui 分支。
- 目前只考虑一种护理硬件“微晶”和一个方案版本；不设计多型号适配、客户端方案版本选择或新旧方案进度迁移。保留成员、方案、执行与微晶标识；测肤补拍的照片版本继续保留。
- 暂不展开同一成员使用多台微晶并行护理的限制；同一台微晶仍只能由 APP 或云台中的一端控制。
- 人脸追踪由云台实现。追丢、追踪目标变化时先暂停/停止，再联网核验，不能拿原核验结果继续。云台不负责认定具体成员身份。
- 当前没有现成通知能力；需提供 APP 通知目标登记及离线提醒投递能力，推送通道待选。
- APP 换人/断网沿用云台规则，计量单位为次数；锁屏/切后台/关闭后的及时停止暂不展开。


## 十一、APP 客户端判断与次数上报边界（本轮补充）

本节记录已确认的客户端连续性与次数规则。

- APP 的换人、断网处理参照云台逻辑。使用者连续时可离线继续；客户端发现换人或连续性失效时先暂停/停止，再联网核验，无网不恢复。客户端负责判断，后端不实现端侧追踪。
- APP 与云台复用 M4-A04 恢复核验接口。该行为是对原流程图 07 页的用户补充，现已补入原流程图 07 页的 app_continuity/app_network/app_revalidation 等分支。
- 锁屏、切换其他 APP、APP 关闭时倾向停止；能否及时停止由客户端实施评估，本版暂不展开，不承诺此时一定成功停止。
- N 与 K 同一单位，均为次数。实际结果以微晶为准，APP／云台负责读取并上传；后端只接收客户端上报的数据，检查归属、去重和累计，不直接读取微晶或判定硬件动作。
- 用户已确认完成条件为 K ≥ N：达到目标次数即完成，例如 N=10、K=10 时完成。剩余次数为 max(N - K, 0)；K 保留合法上报记录去重后的实际累计次数。此确认取代本轮此前的 N < K 写法。

## 本轮补充：配网绑定与通知对象

APP 协助云台联网不要求登录。已登录时先 M2-A07 查询；未绑定显示按钮，用户主动操作 M2-A06 绑定当前账号，成功后 M5-A01 登记通知目标；未登录只联网，不新增绑定/通知目标、不向匿名使用者发通知。云台离线或上报异常时通知实际绑定账号，无绑定不通知。已有绑定不因匿名配网自动清除，绑定冲突不自动覆盖；原账号通过 M2-A08 先解绑，新账号才可绑定。绑定云台不授予成员资料查看权。

运行组件采用 Nginx、Web 后端、PostgreSQL、后台异步任务程序四个自建组件，加上 OSS 对象存储，共五个组件；详见《后端组件图-V5-部署式运行视图》和《运行组件说明》。五模块仍为代码职责划分，不对应五个独立服务。

## 当前已确认规则（本轮同步）


- APP 协助联网与绑定独立：已登录先查状态，未绑定显示按钮，由用户主动绑定；原账号先解绑，新账号才可绑定。B 不能覆盖 A，但可以协助联网。
- 云台绑定用于确定异常通知账号，与成员资料权限无关。解绑不撤销成员授权、不删除历史资料，不改变云台当前任务、不向微晶发停止指令。
- 云台无历史报告/方案列表，只能取得后端当前任务对应结果。后端持久保存云台唯一当前任务、方案关联和已同步进度；重启可恢复，开始/恢复护理仍核验人脸。
- 本次护理结束但方案未完成时，可继续当前任务的方案。新测肤受理即替换云台当前任务，补拍/分析失败不回退；旧资料和进度仍供授权 APP 使用。不得靠旧 ID 或重放请求绕过当前任务限制。
- 云台控制的护理尚未结束时，不允许新测肤。用户先结束本次护理，微晶实际停止、记录同步并收尾后才允许；不要求整个方案达到 N。


接口补充：M2-A07 查询绑定状态，M2-A08 原账号解绑，M3-A06 恢复后端保存的唯一当前任务。D01—D08 剩余技术细节是开发对接项，不是用户待答清单。

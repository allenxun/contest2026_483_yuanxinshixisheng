# 后端对外 HTTP API 设计：五模块与流程对应

## 1. 范围与版本

本版根据用户确认，将旧 M4「护理方案」、M5「护理执行与控制端归属」、M6「护理记录与方案进度」合并为新 M4「护理管理」；旧 M7 通知重编号为 M5。模块图见同目录 `后端模块图-V4-五模块.drawio`。本目录仅保留当前有效图，历史内容通过 Git 追溯。

需求依据为同目录 `后端流程图-V4-APP与云台控制.drawio`（00—07 页）、`后端用例图-V8-APP与云台控制.drawio` 和 `角色边界与流程修订说明.md`。下文 `04 / permit` 表示原流程图第 04 页、节点 ID `permit`，可在 draw.io XML 中定位；所有引用已校验。

**本文仅列供 APP、云台调用的 27 个对外 HTTP API，不包含后端代码中的函数、模块调用或任务入口。** 方法、路径及请求/响应业务要素是设计草案，不代表现有代码已经实现；具体 JSON 字段、鉴权协议、人脸阈值和保留策略尚未冻结；N 与 K 的单位已确定为次数。流程中由后端自动完成的步骤只说明客户端如何查询结果，不另编 API。

| 新编号 | 模块 | 旧编号 | 状态归属 |
| --- | --- | --- | --- |
| M1 | 成员身份与访问授权 | 原 M1 | 成员档案、成员访问关系与核验结果 |
| M2 | 云台与微晶管理 | 原 M2 | 云台档案与在线状态、微晶连接关系与能力 |
| M3 | 测肤任务与报告 | 原 M3 | 测肤任务、照片版本、统一报告及版本 |
| M4 | 护理管理 | 原 M4＋M5＋M6 | 方案与 N、单次执行及微晶占用、实际记录与 K |

M4 统一负责方案、执行、记录与进度。当前只考虑一个方案版本：方案决定 N，单次执行维护控制端与微晶占用，进度按成员及方案累计 K。

### 当前已确认的范围

- **云台**：拍照、人脸追踪、联网、心跳；可作为微晶控制端。云台认证、云台在线/离线说的都是云台。
- **微晶**：实际执行护理的硬件，可由 APP 或云台直接控制。本版只有这一种护理硬件，不设计多型号适配；仍保留微晶标识，以关联当前连接及执行记录。
- **查看授权永久有效**：不按时间自动过期。账号可在 APP 撤销某个人脸对应成员的关联，撤销后该账号不能再查询该成员报告、方案和护理记录；不是删除成员或人脸档案。
- **一个方案版本**：API 不要求客户端选择方案版本，不讨论旧版进度迁移。成员、方案与执行标识仍保留，避免记录归错人或归错方案。照片补拍版本是另一概念，继续保留。
- **不展开多台微晶同时护理同一成员的场景**；同一台微晶仍须保证 APP 与云台不能同时控制。
- **尚无现成通知能力**：本版保留 M5-A01 通知目标登记，并需建设 APP 离线提醒的投递能力；具体通道尚未选择。

### 已确认：绑定、当前任务和进度

- APP 协助联网与绑定独立：已登录先查状态，未绑定显示按钮，由用户主动绑定；原账号先解绑，新账号才可绑定。B 不能覆盖 A，但可以协助联网。
- 云台绑定用于确定异常通知账号，与成员资料权限无关。解绑不撤销成员授权、不删除历史资料，不改变云台当前任务、不向微晶发停止指令。
- 云台无历史报告/方案列表，只能取得后端当前任务对应结果。后端持久保存云台唯一当前任务、方案关联和已同步进度；重启可恢复，开始/恢复护理仍核验人脸。
- 本次护理结束但方案未完成时，可继续当前任务的方案。新测肤受理即替换云台当前任务，补拍/分析失败不回退；旧资料和进度仍供授权 APP 使用。不得靠旧 ID 或重放请求绕过当前任务限制。
- 云台控制的护理尚未结束时，不允许新测肤。用户先结束本次护理，微晶实际停止、记录同步并收尾后才允许；不要求整个方案达到 N。

## 2. 统一接口约束

1. **主体与范围**：APP 配网不要求登录；绑定云台、登记通知目标及账号资料查询要求登录。账号与云台的访问关系及微晶连接关系按相应接口校验，云台独立认证不依赖 APP 账号绑定；合法关系是受控访问的前提；本版不凭客户端提交的成员、云台或微晶 ID 建立信任。APP 查看须存在未撤销的永久授权；云台使用合法认证及测肤/执行上下文。没有全库人脸搜索接口。
2. **执行核验入口**：APP 与云台统一调用 M4-A03，由该请求完成当前人脸核验和新执行登记。客户端无需先调用一个公共人脸核验 API 再拼装启动许可。APP 与云台需要恢复核验时均使用 M4-A04。
3. **接口与本地控制**：后端没有 start/pause/stop 指令转发 API。M4-A03 是登记与准入；M4-A06 是微晶实际停止后的确认。端侧停止不等待后端或网络。
4. **查询无副作用**：报告、方案、任务、执行与进度 GET 不触发重分析、重新生成、启动或恢复。完整/简版是同一数据的受控视图。
5. **写入去重**：逻辑请求与每条有效完成记录使用稳定去重标识；相同标识且同内容重试返回同一结果，相同标识不同内容返回冲突。鉴权先于返回去重结果。具体标识格式待定。
6. **计数来源与累计**：N 与 K 使用相同单位“次数”。实际次数以微晶为准，由 APP／云台采集并上报；后端只使用这些上报数据，检查合法归属并去重累计，不直接读取微晶，也不另行判定硬件动作是否完成。状态观察与次数记录分别处理，启动请求和重复上报不计数。
7. **离线与乱序**：已结束执行仍可接收合法历史记录补传，但不能被迟到 running 状态重开。进度同步成功返回可确认的记录范围，客户端只清理已确认部分。
8. **互斥与切换**：检查占用与登记必须具备原子一致性。未知/未确认停止的执行不可抢占；结束和进度对账未完成时，不得凭过期剩余量启动新执行。本版建议将状态上报与关闭确认分开。
9. **客户端使用者与断网处理**：APP 参照云台逻辑，客户端确认使用者连续时可离线继续；发现换人或原使用者连续性失效时先本地暂停/停止，再联网核验，无网不得恢复。判断及本地动作由客户端负责，后端不做人脸追踪。锁屏、切后台、APP 关闭时倾向停止，但能否及时停止属客户端问题，本版暂不展开、不承诺已实现。
10. **记录归属**：记录固定绑定成员、微晶、方案、执行和控制端；切换控制端不清零已有 K。本版不提供方案版本选择或新旧版本进度迁移。
11. **撤销查看关联**：M1-A03 成功后，该账号后续查询均检查撤销状态，旧登录状态、旧授权标识或原控制端身份不能绕过。APP 应移除该成员入口并停止展示其缓存资料；撤销不删除成员档案、报告或护理记录，也不向微晶发送停止指令。

### 建议的响应分类

| 情况 | 建议表达 |
| --- | --- |
| 新资源登记成功 | 201；执行状态是已登记/待本地确认，不是已运行 |
| 异步任务已受理 | 202，并返回任务引用；是否完成通过查询取得 |
| 查询/幂等重放成功 | 200，保持原业务结果 |
| 凭据失败/范围不足 | 401/403；不可见对象可统一返回 404，具体策略待定 |
| 占用、去重内容或状态冲突 | 409，业务原因区分微晶占用、记录冲突、旧照片版本等 |
| 输入无效、照片缺失 | 400 或 422，并返回可修正信息 |
| 身份不可靠、方案未就绪/已完成、状态未知 | 明确业务结果及不可执行原因，不返回启动许可；最终状态码待定 |
| 算法或外部服务超时 | 同步调用失败或异步任务待重试/失败，不能假成功 |

#### M1-A01 · 人脸授权查看本人资料

- **接口**：`POST /api/v1/member-access-grants`。
- **调用方**：APP。
- **输入要素**：当前账号认证上下文、当前人脸采集资料或受控引用、请求去重标识。 授权用途照片或受控 OSS 对象引用，绑定当前账号及本次授权请求；不接受任意外部 URL。
- **输出要素**：可靠匹配成员的访问授权及成员引用；未匹配或不确定时返回可重试/暂无资料的业务结果。
- **关键规则**：只在账号允许的候选范围内匹配；成功建立永久查看关联，直至账号主动撤销；不在此接口创建新成员；不授予他人查看权；不返回可用于启动护理的许可。旧请求重试不能恢复已经撤销的关联。 图片保存或读取失败时不得当作人脸核验成功；用途/归属不符的对象拒绝使用。

#### M1-A02 · 查询当前账号已有成员访问关系〔查询导航配套〕

- **接口**：`GET /api/v1/me/member-access-grants`。
- **调用方**：APP。
- **输入要素**：当前账号认证上下文。
- **输出要素**：仍有效的成员查看关系及可用于本人报告/方案查询的成员引用。
- **关键规则**：仅返回当前账号尚未撤销的查看关联；授权不自动过期；返回可用于撤销的关联标识；不提供全库成员检索。

#### M1-A03 · 撤销当前账号与某个人脸对应成员的查看关联

- **接口**：`DELETE /api/v1/me/member-access-grants/{grantId}`。
- **调用方**：APP 中已登录的关联所属账号。
- **输入要素**：该账号自己的查看关联标识 `grantId`。
- **输出要素**：204，撤销成功；同一账号重复撤销已撤销的关联也视为完成。
- **关键规则**：不能撤销他人的关联；后续拒绝该账号查询对应成员的报告、方案与护理记录；原有登录状态或旧授权请求重试不能恢复查看权限。APP 移除成员入口并停止展示该关联的缓存资料。只撤销账号的查看关联，不删除成员、人脸档案、报告或护理记录；不自动影响其他账号已有的关联。

#### M2-A01 · 云台认证或恢复连接后重新认证

- **接口**：`POST /api/v1/gimbal-sessions`。
- **调用方**：云台。
- **输入要素**：云台身份与云台凭据；具体凭据协议待定。
- **输出要素**：认证会话及云台身份上下文，或认证失败原因。
- **关键规则**：不创建或改变云台归属；凭据失败不登记为可信在线；重复认证不创建护理执行。

#### M2-A02 · 上报心跳和云台已知工作状态

- **接口**：`POST /api/v1/gimbals/{gimbalId}/heartbeats`。
- **调用方**：已认证云台。
- **输入要素**：心跳去重/顺序依据、清醒/休眠、当前任务与执行引用及已知状态、云台可检测并上报的异常代码与摘要；异常枚举、严重度及具体频率待定。
- **输出要素**：接收确认、后端记录时间。
- **关键规则**：更新云台在线信息；单次超时不立即离线；执行状态摘要可供对账，但不累计完成量、不自动创建执行、不仅凭心跳释放占用。

#### M2-A03 · 查询云台状态

- **接口**：`GET /api/v1/gimbals/{gimbalId}/status`。
- **调用方**：APP；关联且已认证的云台。
- **输入要素**：云台引用与调用主体认证上下文。
- **输出要素**：在线/离线、清醒/休眠、最近上报时间、已知工作/执行状态及过期或未知标记。
- **关键规则**：检查已有云台访问范围；云台离线不代表微晶停止；不得伪装成云台当前实时状态。

#### M2-A04 · 登记已连接微晶的能力与状态观察

- **接口**：`POST /api/v1/microcrystal-observations`。
- **调用方**：APP 或云台。
- **输入要素**：微晶标识、能力、本次连接上下文、实际观察状态及时间、去重标识。
- **输出要素**：微晶引用、已接收能力与观察版本、可信归属校验结果。
- **关键规则**：登记不等于首次绑定授权，不允许以请求体覆盖他人归属或执行占用；观察不能抢占旧执行。能力补齐后，等待中的方案可继续生成；客户端通过方案查询获知结果，同一能力版本重复上报不重复生成；配对与能力字段格式待定。

#### M2-A05 · 读取后端已登记微晶能力〔能力查询配套〕

- **接口**：`GET /api/v1/microcrystals/{microcrystalId}/capabilities`。
- **调用方**：APP 或云台。
- **输入要素**：微晶引用、已有连接/访问权限。
- **输出要素**：能力版本、已知状态与更新时间。
- **关键规则**：不替代开始前本地微晶就绪检查；不能据此宣称微晶没有被占用；占用在申请执行时检查。

#### M2-A06 · 用户主动绑定云台到当前账号

- **接口**：`PUT /api/v1/me/gimbal-bindings/{gimbalId}`。
- **调用方**：已登录且正在协助该云台联网的 APP。
- **输入要素**：当前账号认证上下文、云台标识、本次配网关联与可验证的云台配对凭据；具体凭据协议待定。
- **输出要素**：当前账号与云台的绑定关系，或凭据无效、已有其他账号绑定等明确失败原因。
- **关键规则**：APP 协助联网不要求设备未绑定。已登录 APP 先用 M2-A07 查询状态：未绑定显示绑定按钮，已绑定本人显示已绑定，已绑定他人不允许绑定。用户主动点击才调用本接口，配网不自动绑定。账号由认证上下文确定，本次配对证明必须可验证；绑定时再次原子校验未绑定或已绑定本人，不能覆盖他人。相同账号重复绑定幂等。A 未解绑时 B 仍能协助联网但不能绑定；A 经 M2-A08 解绑后 B 才可绑定。云台绑定用于异常通知，不授予成员资料查看权，不决定云台当前测肤任务的访问资格。未登录只配网，不绑定/登记通知目标；联网与绑定结果分别显示。

#### M2-A07 · 配网时查询云台绑定状态

- **接口**：`GET /api/v1/gimbals/{gimbalId}/binding-status`。
- **调用方**：已登录且持有本次合法配对上下文的 APP。
- **输入要素**：云台标识、当前账号认证上下文及可验证的配对上下文；证明放在认证上下文/请求头，协议由开发确定。
- **输出要素**：未绑定、已绑定本人、已绑定其他账号三种状态；不返回其他账号的姓名或联系方式。
- **关键规则**：仅用于配网界面决定是否显示绑定按钮；不是建立绑定。B 可协助已绑定 A 的云台联网，但不能绑定。不能仅凭任意云台 ID 探查；实际绑定仍须 M2-A06 再次校验，防止查询后状态变化。未登录只配网，无需查询账号绑定状态。

#### M2-A08 · 原账号解除云台绑定

- **接口**：`DELETE /api/v1/me/gimbal-bindings/{gimbalId}`。
- **调用方**：当前绑定所属账号的已登录 APP。
- **输入要素**：云台标识、当前账号认证上下文。
- **输出要素**：解除绑定成功，云台可被新账号绑定；不返回其他账号信息。
- **关键规则**：只允许原绑定账号解绑；不得删除其他账号的新绑定。同一账号对已解除且未被他人重新绑定的关系重复请求视为完成；新绑定已建立时旧账号重试不得解除新关系。解绑后不再按原关系通知 A，排队通知及重试须复核当前绑定。解绑不撤销任何成员查看授权，不删除报告/方案/记录，不改变云台当前任务、不发送停止指令；设备绑定不替代成员授权。原账号无法登录的例外处理暂不扩展本版自助流程。

#### M3-A01 · 提交三视角测肤任务

- **接口**：`POST /api/v1/skin-assessment-tasks`。
- **调用方**：已认证云台；APP 测肤不开放。

- **输出要素**：任务引用和接收/处理中状态；已处理同一请求则返回已有任务；格式缺失时返回需修正信息。
- **关键规则**：先校验云台身份和照片归属，再处理去重。发起新测肤前，云台控制的原护理执行须实际停止、记录同步并收尾；未结束或状态未知时拒绝新任务，不自动停止护理。新任务受理和云台唯一当前任务关联的替换原子完成，不等待报告/方案成功；补拍或分析失败不回退。格式无效等未受理请求不替换。相同请求重试不重复建任务，也不能把云台关联重新指向已被替换的旧任务；对旧请求返回已被替换的受限结果，不提供旧报告/方案。新任务建立不删除旧任务资料与进度。照片质量与同人检查异步完成。 受理后图片保存/读取失败体现任务异常，不回退云台当前任务；未受理请求不替换。处理状态不等于图片已可用。

#### M3-A02 · 补拍并提交新照片版本

- **接口**：`PUT /api/v1/skin-assessment-tasks/{taskId}/photo-versions/{photoVersion}`。
- **调用方**：该任务所属且仍以该任务为当前任务的已认证云台。
- **输入要素**：原任务引用、新版本号、该版本完整视角清单及新增/替换照片引用；未替换照片可复用受控引用。 新照片版本的视角和 OSS 引用；未替换照片仅复用本任务可访问的引用。
- **输出要素**：原任务引用、新版本处理状态。
- **关键规则**：补拍沿用任务；相同版本相同内容幂等，不同内容冲突；新版本触发重分析；旧版本迟到结果不得覆盖新版本。 后端逐次校验 taskId 仍是该云台当前任务；不得通过补拍历史任务恢复其访问入口，补拍不创建另一个测肤任务。 结果图片也按任务/照片版本关联；重试和旧版本回调不能覆盖新版本图片。

#### M3-A03 · 查询测肤任务及补拍要求

- **关键规则**：纯查询不触发分析或新建任务；尚未可靠归档的任务不因 APP 声称成员身份就开放。 云台只可读取后端当前任务关联指向的 taskId；旧任务被替换后，即使知道 ID 也拒绝获取其报告/方案。APP 按独立成员查看授权读取，不受云台当前指针变更影响。

#### M3-A04 · 列出可访问报告〔查询导航配套〕

- **关键规则**：APP 按未撤销的成员查看授权查询报告。云台仅可取得后端当前任务对应报告的简版，不能查询历史报告；绑定账号或知道旧 reportId 均不能绕过限制。传 full 不扩大权限；报告就绪即可返回，不等待方案。 图片与正文使用相同访问范围；不得直接返回公开永久图片地址或算法临时地址冒充已归档结果。

#### M4-A03 · 当前人脸核验、取得本人方案并登记新执行

- **接口**：`POST /api/v1/care-executions`。
- **调用方**：APP 或云台。
- **输入要素**：新执行请求去重标识、目标微晶/连接上下文、当前人脸；APP 提供有权使用的所选方案；云台提供当前任务关联及本轮追踪标识，方案由后端从当前任务确定。 当前人脸照片内容或受控 OSS 引用，绑定本轮请求、控制端及任务/方案上下文。
- **输出要素**：成功时返回执行引用、固定控制端、已核验成员关联、方案、N、已有 K、剩余量、执行必需参数及本次核验关联；返回“已登记/待端侧确认”，不宣称已运行。
- **关键规则**：服务端确定控制端身份，核验当前使用者，检查微晶能力、方案就绪/可执行/未完成及占用；互斥检查与登记须原子保证。重复同请求返回同执行，并带重放标记与当前执行状态，不产生新的核验有效性或重新启动；不能只重放旧的“可启动”结果。换人不返回原成员方案。客户端核对请求/追踪仍有效、本次核验仍适用和本地微晶就绪后才首次启动；无法确定此前是否启动时先对账，不重发启动。 云台方案必须属于其唯一当前测肤任务；不能按匹配人脸领取其他任务的历史方案。当前任务未被替换且方案未完成时，可跨次护理继续，后端保留 N/K；若旧执行已关闭，则登记新执行而非重开旧执行。新测肤取代当前任务后，云台不能用旧任务/旧成功请求重放取回方案，APP 的合法历史方案使用不受影响。 照片保存/读取失败不得返回本轮核验通过；旧对象不能仅靠重新提交 ID 充当本轮有效采集。

#### M4-A04 · 使用者连续性失效后重新核验恢复条件

- **接口**：`POST /api/v1/care-executions/{executionId}/revalidations`。
- **调用方**：原执行的 APP 或云台控制端。
- **输入要素**：原执行引用、当前人脸、本轮客户端核验关联（云台对应新追踪目标）、客户端上报的微晶实际状态、请求去重标识；提交可同步的待补记录或先调用 M4-A05。 新一轮当前人脸照片内容或受控 OSS 引用，绑定原执行与本轮核验关联。
- **输出要素**：同一成员且仍可恢复时返回原方案、保留进度和本次恢复核验结果；其他成员/不确定/不满足条件时明确不允许恢复原执行。
- **关键规则**：APP 与云台共用；原控制端、同一成员、暂停且仍可恢复时沿用原方案和进度；已关闭执行不重开。云台还须确认方案属于其当前任务。响应回来时再次换人或连续性失效不得恢复。换人先确认原微晶停止并完成收尾：云台须为新使用者发起新测肤，不能搜索其历史方案；APP 可使用有权查看的本人方案重新申请。 图片失败不得恢复护理，旧图片引用不得绕过本轮连续性及采集有效性检查。

#### M4-A05 · 同步实际状态与有效完成记录

- **接口**：`POST /api/v1/care-executions/{executionId}/observations`。
- **调用方**：原执行的合法控制端；允许该控制端补传历史执行记录。
- **输入要素**：执行引用、批次/记录稳定去重标识、客户端依据微晶反馈得到的实际状态、有效完成次数及其记录顺序/发生关联；次数均使用与 N 相同的单位。
- **输出要素**：逐记录接收/重复/拒绝结果、可确认已同步的记录标识、后端累计次数 K、剩余次数 max(N - K, 0)、完成状态 K ≥ N 及执行已知状态。
- **关键规则**：必须检查成员、微晶、方案与控制端归属；后端以合法 APP／云台上报的数据为准，不直接校验微晶原始反馈；相同记录重传不重复计数，不同内容复用标识冲突；乱序旧状态不得覆盖新状态或重开已结束执行；迟到有效记录仍按原方案归档。上报 K 不是覆盖总量的权力，启动/指令发送不计完成。终止状态报告本身不触发微晶操作。

#### M4-A06 · 确认本地已停止并完成执行收尾

- **接口**：`POST /api/v1/care-executions/{executionId}/closure-confirmations`。
- **调用方**：原执行控制端。
- **输入要素**：客户端上报的微晶已停止状态、原执行引用、结束原因、本次已完成次数记录及同步确认信息、去重标识。
- **输出要素**：已关闭且占用释放，或仍待实际状态确认/记录对账。
- **关键规则**：这是停止后的确认，不是远程停止命令；以后端收到的客户端“微晶已停止”状态为依据，后端不直接向微晶取证；不能凭“已发送停止”释放占用；状态未知拒绝抢占。建议在记录未对齐时保持不可新启动，避免新执行取得过期剩余量；完整对账机制待实施设计。

#### M4-A07 · 查询执行及恢复联网后的对账状态

- **接口**：`GET /api/v1/care-executions/{executionId}`。
- **调用方**：原执行控制端；具备成员查看权的 APP。
- **输入要素**：执行引用与合法主体上下文。
- **输出要素**：固定成员/微晶/方案/控制端、已知实际状态及新鲜度、记录确认状态、是否已关闭；按权限裁剪。
- **关键规则**：只读；重连或查询不自动开始/恢复；原控制端可补传本次执行记录，但不能据此取得成员查看权；APP 的成员查看关联撤销后，不得通过本接口读取该成员资料或护理记录。 云台仅获取原执行的最小对账状态和记录确认信息；不能借历史执行详情取得旧报告、方案内容或成员历史列表。

#### M4-A08 · 查询方案累计进度

- **接口**：`GET /api/v1/care-plans/{planId}/progress`。
- **调用方**：已授权 APP；具备当前已核验执行上下文的云台。
- **输入要素**：固定方案、授权或已核验执行上下文。
- **输出要素**：目标次数 N、后端已同步次数 K、剩余次数 max(N - K, 0)、完成状态 K ≥ N 及最后同步信息。
- **关键规则**：云台不以该接口绕过执行前核验领取方案；离线未同步量不伪装成后端已知实时总量；不按会话数/下载数计数。 云台必须同时具备当前任务对应方案及合法已核验执行上下文；不能查询其他历史方案进度。后端持久保存去重累计 K，重启和换绑不清零。

#### M4-A09 · 查看本人护理记录

- **接口**：`GET /api/v1/members/{memberId}/care-executions`。
- **调用方**：已授权 APP。
- **输入要素**：成员引用、分页与方案/日期等筛选条件。
- **输出要素**：本人执行历史、状态与有效完成摘要。
- **关键规则**：执行结束与方案达标分别展示；不混用不同成员、方案的记录。

## 5. 客户端调用示例

### 5.1 APP 查看与护理

1. `M1-A01` 人脸授权 → 必要时 `M1-A02` 查本人访问关系。
2. `M3-A04/A05` 查报告 → `M4-A01/A02` 查方案；报告不等待方案生成。
3. APP 本地连接微晶 → `M2-A04` 上报能力 → `M4-A03` 携带当前人脸申请新执行。
4. 收到 `M4-A03` 的成功响应后，确认本次核验仍适用、执行没有启动过且本地微晶就绪，再发送本地启动操作。
5. `M4-A05` 同步微晶实际状态和有效完成记录；重复请求不重复累计。
6. 暂停/结束先本地执行；随后 `M4-A05` 同步实际记录，`M4-A06` 确认收尾；`M4-A08` 查方案累计结果。

### 5.2 APP／云台发现换人或连续性失效后的恢复

1. 当前人脸及本轮核验关联 → `M4-A03` → 客户端确认响应仍对应当前使用者 → 本地启动。
2. 客户端确认使用者连续时可离线继续；以微晶反馈记录实际完成次数，联网调用 `M4-A05`。
3. 云台追丢或客户端发现换人、使用者连续性失效时，立即本地暂停/停止；无网不恢复，不因重新看到人脸自动恢复。
4. 网络恢复先补传可同步记录，再 `M4-A04` 核验当前人脸与原方案成员。
5. 同一成员、原执行仍可恢复且尚未完成：使用返回的原方案与进度，由客户端确认当前使用者及微晶条件后继续；已结束执行不能重开。
6. 其他成员：不继续原方案；原执行停止及对账后，云台为新成员先发起新测肤，不能找回其历史方案；APP 可选有权方案再 `M4-A03`。本版不要求选择方案版本，也不新增云台手动选姓名步骤。

### 5.3 提交测肤并查询报告与方案

1. 云台调用 `M3-A01` 提交三视角照片，取得任务引用。
2. `M3-A03` 查询任务结果；需要补拍时，沿用该任务调用 `M3-A02` 提交新照片版本。
3. 报告就绪后，`M3-A05` 即可查询；此时方案可能仍在等待条件或生成中。
4. 已授权 APP 通过 `M4-A01/A02` 查询方案状态与内容；云台在 `M4-A03` 当前核验成功后取得本人执行方案。
5. 若方案尚未就绪或微晶状态不允许执行，按返回原因等待或更新微晶状态；方案就绪后重新申请执行，不自动启动。

### 5.4 配网、账号绑定与云台异常提醒

1. APP 协助云台联网；无论 APP 是否登录，云台都可通过 M2-A01 独立认证。
2. APP 未登录：仅完成配网，不新增绑定、不登记通知目标、不向匿名使用者发通知。已存在的绑定不会被匿名配网自动清除。
3. APP 已登录：先 M2-A07 查询；未绑定显示按钮，用户主动点击后 M2-A06 绑定；已绑定本人显示状态；已绑定他人只能协助联网。原账号 M2-A08 解绑后，新账号才可绑定。通知目标由 M5-A01 登记，登录/退出时目标维护由开发对接。
4. 后端发现云台离线，或通过 M2-A02 收到云台异常时，自动选取绑定账号并投递通知；无绑定不发通知。异常类别和触发阈值待客户端对接。
5. 收到通知的 APP 可用 M2-A03 查询最新已知状态。云台离线不表示微晶已停止。

### 5.5 补充调用链：恢复云台当前任务

云台认证 → M3-A06 取得后端保存的唯一当前任务 → M3-A03 获取本次处理状态 → M3-A05 获取本次简版报告 → M4-A03 核验登记新执行（或 M4-A04 恢复尚可恢复的原执行）→ 获取后端 N/K。任务恢复不自动启动，不提供历史列表。

## 6. 当前结论与剩余事项

### 6.1 已确定的后端业务边界

- APP 换人、断网参照云台逻辑；客户端负责判断及本地暂停/停止，后端提供核验与记录接口。APP 和云台共用 M4-A04 恢复核验，不新增另一套 API。
- 连续使用期间可离线继续；换人或使用者连续性失效后先暂停/停止并联网重验，无网络不能恢复。
- 锁屏、切到其他 APP、APP 被关闭时希望停止，但是否来得及停止由客户端实施时评估；本版暂不展开，也不写成保证能停止。
- N、K 都是次数。微晶产生实际结果，APP／云台采集并上传，后端只使用上传的数据，不直接读取微晶或验证具体硬件动作。
- 后端对合法上报检查成员、微晶、方案、执行和控制端关联，去重累计 K，以 K ≥ N 判定完成，剩余次数为 max(N - K, 0)。客户端重复上报同一记录不能重复计算。
- 永久查看授权与主动撤销、一个方案版本、一种微晶、不展开多微晶并行、通知能力需建设，均已确认。

### 6.2 已确认：达到目标次数即完成

完成条件为 **K ≥ N**。例如 N=10，K=10 时方案已经完成；K 超过 N 时也保持完成。剩余次数为 **max(N - K, 0)**。

K 按合法客户端上报的实际记录去重累计；不因为超过目标就把实际 K 截成 N。方案完成后不再登记新的执行；已发生但迟到的合法记录仍可去重补传，不能因此重开执行。客户端与后端使用同一完成条件；后端以已收到的记录计算，离线尚未同步的次数不伪装成已知数据。

### 6.3 开发对接项，不要求用户逐项决策

- APP 登录凭据形式、配网证明、绑定状态查询与解绑的鉴权协议、微晶连接关系如何登记，由开发在正式鉴权对接前确定。当前接口继续以已有合法账号及访问范围为前提，不提供任意成员或云台访问。
- 通知推送通道、JSON 字段、记录去重标识等在详细接口对接时确定。当前没有通知平台，需建设；不因此扩展后端代码内部接口。
- 客户端如何识别换人、如何读取微晶次数和及时停止，由客户端实现；本轮不再要求用户定义微晶动作计量细节或底层停止证据。

### 6.4 图片存储约定

云台及 APP 上传的照片、测肤结果中的图片统一保存至 OSS；PG 保存对象引用和任务/成员归属。现有照片或受控引用字段对应 OSS 对象，不能凭对象地址绕过接口访问范围。APP 拍照仍包括人脸授权/执行核验等用途，不开放 APP 测肤。本轮不新增 HTTP API；受控上传方式、图片访问和保存失败补偿由开发对接。

### 6.5 图与 API 交叉检查后的开发接口事项

- 图示默认由现有业务请求携带照片、后端转存 OSS；没有新增独立文件管理接口，也不向客户端提供后端内部存储函数。M1-A01、M3-A01/A02、M4-A03/A04 必须明确照片内容的传输格式；若改为直传 OSS，须另行补全上传授权和上传完成确认协议，不能让客户端凭空提供可信对象引用。
- M3-A05 返回受控图片访问描述；图片实际下载采用鉴权代理或短期凭证等方式，由开发完成协议。特别检查撤销成员授权、替换云台当前任务后已发出的图片访问凭证如何失效，不能把链接隐藏视为权限已收回。
- M5-A01 登记/更新目标已有；退出登录、切换账号后的旧目标失效仍须接入账号会话协议。当前清单已列 D02，不把尚未实现的注销动作当成已有独立 API。
- M2-A08 的入口需要 APP 能定位当前绑定云台：可从配网/已知云台详情进入；若产品另需账号所有云台列表，再明确列表需求后补接口，不在本次检查中默增列表能力。

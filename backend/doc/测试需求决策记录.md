# 测试需求决策记录

本文件记录测试清单逐项评审的用户决定。已确认结论优先于旧文档中的设计假设；全部问题讨论完后统一同步 API、流程、用例和网页。未明确事项不视为已确认。

## D01-1：云台配网、绑定和换绑

状态：已确认。

- 采用原账号先解绑、新账号再绑定的方式。
- 云台已经绑定 A 时，B 仍可协助联网，但不能绑定或覆盖 A 的绑定。
- APP 协助云台联网时查询绑定状态；未绑定时可以显示“绑定”按钮，由用户主动操作绑定，不再采用配网后自动绑定的假设。
- 已绑定当前账号时显示已有绑定状态；已绑定其他账号时不允许绑定。查询结果仅用于展示，提交绑定时后端仍须再次校验，避免状态变化后被覆盖。
- 未登录仍只协助联网，不新增账号绑定。

## D01-2：解绑、成员授权与云台数据范围

状态：已确认。

- 用户选择保留成员查看授权。解绑云台不撤销已建立的人脸/成员查看授权，不删除报告、方案或护理记录；成员查看关联须单独主动撤销。
- 云台绑定与成员资料权限无关，用于确定云台异常通知账号，不据此授予成员资料访问权。
- 云台只能新增测肤报告，不能查询历史报告。云台能获取的报告仅限于本次新上传测肤任务产生的报告；方案同理，只能获取本次任务对应的方案，不能查询或领取历史任务的方案。
- “获取本次结果”与“查询历史资料”必须在后续图和 API 中区分。不能通过成员 ID、历史报告 ID、历史方案 ID 或单纯人脸匹配扩大云台可取数据的范围。

## D01-3：云台重启后恢复本次任务

状态：已确认（选择 1）。

- 云台保存本次任务编号，重启后可以恢复原未完成任务，继续取得该任务的报告和方案，不要求仅因重启重新测肤。
- 恢复原任务不开放历史任务列表或任意历史报告/方案查询。
- 开始或恢复护理仍须核验当前使用者，重启不自动启动或恢复微晶护理。

本轮已同步到文档、图、API 与网站；技术细节统一列为开发对接项。

## D01-4：跨次护理继续当前方案与进度保存

状态：已确认（选择 1）。

- 一次护理结束但方案尚未完成时，可在后续继续云台当前任务对应的原方案；每次开始/恢复仍核验当前使用者。
- 后端持久保存方案目标 N、去重累计的已上传次数 K 及任务/方案关联；客户端暂存离线未上传记录，联网补传。
- 本条不授予云台历史方案列表或任意历史任务查询能力。

## D01-5：多人先后测肤时的云台任务范围

状态：已确认（选择 1）。

- 云台只保留最近一次测肤任务的关联，不按人脸恢复多人的历史未完成任务。
- 甲的方案未完成，乙在同一云台完成新的测肤后，云台当前任务转为乙的任务；甲返回时不能通过这台云台恢复旧方案，须重新测肤。
- 甲旧方案、历史记录及进度继续保存在后端，已获成员查看授权的 APP 可查看并继续护理。
- 因新任务取代云台当前关联而产生的旧任务查询限制必须由后端校验，不能仅靠云台隐藏入口。

本轮已同步到文档、图、API 与网站；技术细节统一列为开发对接项。

## D01-6：新测肤提交成功即替换当前任务

状态：已确认（选择 1）。

- 新测肤任务提交成功、被后端受理后，立即替换该云台的当前任务关联，不等待新报告或新方案生成。
- 新任务后续需要补拍或分析失败，也不恢复旧任务的云台访问入口；补拍仍沿用新任务。
- 旧任务的报告、方案及进度不被删除，仍按成员授权供 APP 使用。
- 后端未受理的新请求不视为提交成功；同一次提交重试应按既有去重规则处理。

本轮已同步到文档、图、API 与网站；技术细节统一列为开发对接项。

## D01-7：当前护理结束后才允许新测肤

状态：已确认（选择 1）。

用户先结束云台控制的本次护理，微晶实际停止、记录同步并完成收尾后，才允许提交新测肤任务。后端及客户端共同检查；不因发起测肤自动中断护理，不要求整个方案完成 N 次。

## MVP 架构补充决策（2026-09-10）

状态：已确认。

- APP 第一版使用手机号登录，客户端先支持 Android；具体手机号验证、刷新和退出协议由开发完成。
- 报告展示所需图片随报告保存，人脸参考照片按算法需要保存，临时核验照片不默认长期保留；具体清理周期在真实用户试用前明确。
- Web 后端采用 Java；异步 Worker 暂时采用 Python，复用 Python 算法和大模型集成，通过 PG 任务表交接。
- 维持五模块、五运行组件、14 张当前设计表和默认不写 JOIN 的要求。账号会话等基础契约尚需补齐，不能把 27 个业务 API 当作完整认证协议。

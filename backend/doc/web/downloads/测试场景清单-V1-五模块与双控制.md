优先级为本轮建议：**P0** 是核心链路、权限、错误启动与错误计数等必须优先覆盖的场景；**P1** 是查询、异常恢复和配套能力。P1 不是可以省略的测试。

验证范围：**后端**通过 HTTP 调用及业务状态核对；**集成**需要真实或可控模拟的算法、大模型、推送/异步程序；**联调**需要 APP、云台或微晶参与。模拟通过不能代替真实设备停止、人脸连续性或手机实际收到通知的验证。表中的 API 用于定位请求入口或结果查询，后台任务不是新增内部接口测试清单。

依赖“—”表示业务预期已有依据，不代表无需环境或数据；D 编号见文末。开发对接条件未落实时标记“待测试条件准备”，不得将其记为通过，也不擅自指定状态码、阈值或时长。

## 开发对接项与测试准备

### 用户已经决定什么

手动绑定及原账号先解绑；绑定与成员权限独立；云台仅保留当前任务、重启可恢复；后端保存 N/K；跨次可继续当前方案；新测肤受理即替换且失败不回退；原护理先结束、停止并收尾后才允许新测肤。无需再逐项请用户确认。完整记录见《测试需求决策记录》。

### 开始执行前准备什么

1. 账号与成员：账号 A/B、成员甲/乙，分别准备有查看授权、未授权和已撤销的关系；云台绑定不是成员授权。
2. 云台与微晶：准备未绑定、绑定 A 的云台状态，以及一个能由 APP/云台分别控制的微晶。测试“同一微晶两端抢占”，不要求两台微晶同时护理同一人。
3. 任务与方案：准备无当前任务、处理中、需补拍、失败、报告就绪、方案就绪、已被新任务替换的旧任务。后端同时保留旧资料，云台只能取当前结果。
4. 次数与执行：N=10，K=0/9/10/11；另准备 K=3 的跨日恢复场景，以及运行、暂停、停止待确认、已关闭和补传待确认的数据。
5. 故障条件：能主动断网、模拟响应丢失/重复上报、算法或大模型失败、推送失败和工作进程重启。
6. 证据：保存请求/响应、任务及进度状态；端侧动作和实际通知须结合设备/手机观察。测试使用获准的人脸照片，避免混入真实用户资料。

## 本轮不纳入的范围

- APP 拍照测肤：非 MVP，不为它设计本版业务成功链路；仍检查它不能越过当前云台提交限制。

# 后端运行组件说明

## 五个运行组件

本图是接近部署视角的运行组件图，表达进程、服务和通信，不表示服务器数量，也不是五模块的重新分组。Nginx、Web、PG 和异步程序可在一台服务器部署，OSS 使用独立托管对象存储；Web 后端使用 Java，异步程序暂时使用 Python，采用独立工程和镜像，通过 PG 工作项交接；可同仓管理，但不共享一份可执行业务代码。

| 组件 | 职责 | 对应业务模块 |
| --- | --- | --- |
| Nginx | HTTPS 入口、转发 HTTP 请求、托管静态页面 | 基础设施，不算业务模块 |
| Web 后端（Java） | 27 个对外 HTTP API、账号/云台认证、配网绑定、当前人脸核验、查询及实际记录写入 | M1—M5 的客户端入口 |
| PostgreSQL | 成员/授权、云台绑定、报告、方案、执行/进度、待处理任务及通知投递状态 | 五模块共享的持久化设施 |
| OSS 对象存储 | 保存云台、APP 拍照上传的图片，以及测肤结果中的图片；PG 保存对象引用与业务归属 | M1/M4 核验照片、M3 测肤原图与结果图的存储设施 |
| 后台异步任务程序（Python） | 测肤分析与报告归档、方案生成、云台离线检测、异常通知和失败重试 | M3、M4、M5 的异步处理；监测 M2 的心跳状态 |

## 为什么建议保留异步任务程序

测肤和大模型方案生成需要在 HTTP 请求结束后继续处理，客户端查询进度；离线检测需要在没有新请求时检查最后心跳，通知投递也需要失败重试。独立工作进程可以承接这些任务，避免慢任务占用 Web 请求处理。当前人脸执行前核验仍由 Web 请求调用算法并返回核验结果。

初版以 PG 任务表保存待处理任务、状态、重试次数及下次执行时间，Web 将业务状态和任务同事务入库。工作程序原子领取任务，使用租约/超时恢复和幂等结果写入，防止进程重启丢任务；同一任务不得产生重复业务结果。任务领取方式与重试间隔在实施时细化，不是新增对外 HTTP API。当前没有证据要求额外 Redis 或消息队列，不因异步任务额外增加消息队列组件。

## 外部协作与边界

- APP、云台经 Nginx 调用 Web API；云台自主认证不依赖 APP 登录。
- 算法服务：Web 调用人脸匹配完成当前核验；异步程序调用照片质量与测肤分析。
- 大模型服务：异步程序生成方案与目标 N，后端校验后保存。
- 通知通道：异步程序向实际绑定账号的有效 APP 目标投递云台离线/已上报异常；无绑定不通知。通道待选，退出登录与账号切换时旧通知目标的失效协议待定。
- APP 协助配网，已登录先 M2-A07 查状态，用户点击后 M2-A06 绑定，成功后 M5-A01 登记通知目标；未登录只联网，不新增绑定/通知目标、不向匿名使用者发通知。既有绑定不因匿名配网被清除；不能抢占其他账号绑定。
- APP 或云台在本地控制微晶，采集次数后上传；后端不直连微晶，不转发开始/暂停/停止。
- OSS 是本版必需组件，保存云台及 APP 上传照片、测肤结果图片。PG 只保存对象引用、元数据及成员/任务归属，不以业务数据卷代替 OSS。图示上传路径为 APP/云台 → Nginx → Web → OSS，异步程序读取原图、将算法返回的结果图归档 OSS；永久引用以 OSS 对象为准。

## 模块与组件的区别

M1—M5 说明代码各负责什么；这张图说明运行时有哪些程序和服务、彼此如何通信。一个业务模块可以同时在 Web 与工作程序中执行，PG 和 Nginx 也不对应独立业务模块。

## 当前已确认规则（本轮同步）


- APP 协助联网与绑定独立：已登录先查状态，未绑定显示按钮，由用户主动绑定；原账号先解绑，新账号才可绑定。B 不能覆盖 A，但可以协助联网。
- 云台绑定用于确定异常通知账号，与成员资料权限无关。解绑不撤销成员授权、不删除历史资料，不改变云台当前任务、不向微晶发停止指令。
- 云台无历史报告/方案列表，只能取得后端当前任务对应结果。后端持久保存云台唯一当前任务、方案关联和已同步进度；重启可恢复，开始/恢复护理仍核验人脸。
- 本次护理结束但方案未完成时，可继续当前任务的方案。新测肤受理即替换云台当前任务，补拍/分析失败不回退；旧资料和进度仍供授权 APP 使用。不得靠旧 ID 或重放请求绕过当前任务限制。
- 云台控制的护理尚未结束时，不允许新测肤。用户先结束本次护理，微晶实际停止、记录同步并收尾后才允许；不要求整个方案达到 N。


接口补充：M2-A07 查询绑定状态，M2-A08 原账号解绑，M3-A06 恢复后端保存的唯一当前任务。D01—D08 剩余技术细节是开发对接项，不是用户待答清单。

## 图片存储与访问

- 云台测肤原图和补拍图、APP 人脸授权/执行核验等用途上传的照片、测肤结果中的图片均存入 OSS。APP 拍照测肤仍为非 MVP，本次不新增该业务能力。
- Web 校验请求主体及照片用途，保存 OSS 对象引用和归属；异步任务读取原图并归档结果图，避免仅保存算法服务临时链接。
- 图片读取必须沿用报告/任务的访问范围：APP 按成员授权、云台按唯一当前任务。不能通过知道对象地址越权获取图片，不设置公开照片目录。
- 图中展示经后端转存的路径；是否采用受控直传、访问签名、对象命名、存储期限、备份及失败补偿由开发设计，不在本轮虚构接口。上传失败不得保存为可用图片，结果图保存失败应有明确任务状态及重试/补偿处理。

## 双语言工程边界

Java 负责对外 API、账号授权、绑定、当前任务、执行占用、次数入账与收尾；Python 负责异步测肤归档、方案生成及通知等任务。两边共享 PG 的版本化任务/结果契约，数据库迁移只维护一套。同步人脸核验由 Java 调用算法 HTTP API/Java SDK，不排入异步队列后等待。字段写入和跨语言兼容规则见 [技术架构第 4 节](技术架构设计-V1-MVP.md)。

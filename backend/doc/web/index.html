4. 两条 SSE 接口

M2-A09 · 云台 AI 文本问答

•接口：POST /api/v1/gimbal-ai/messages。

•调用方：仅 GIMBAL Bearer；APP 主体拒绝。

•请求：严格 JSON {"text":"..."}，只允许 text，去空白后 1—2000 字符。

•响应：text/event-stream；Java 将请求真实转发到 llm-rag 的 POST /internal/v1/ai/responses:stream，解析、校验并重编码 response.accepted、response.delta、response.completed 或 response.failed。

•状态：已实现/待完整 E2E。真实下游流已完成联调；目标 dev 后端尚未以真实云台 token 完成端到端验收。

•限制：无本地会话历史、不存储或回传 continuation_state，不发送 Last-Event-ID，不重放；客户端重试会创建一个新问题。客户端断开会关闭下游连接。

M3-A07 · 测肤报告播报流

•接口：GET /api/v1/skin-assessment-tasks/{taskId}/report-narration-stream。

•调用方：仅 GIMBAL Bearer；必须仍是该云台当前任务，且报告已 report_ready。

•响应：text/event-stream，固定顺序 start → text_delta → text_delta → done，seq=1..4，每个事件即时 flush。

•当前正文：本次完成额头、左脸、右脸和下巴四个区域的皮肤检测。额头61分，左脸39分，右脸67分，下巴45分。

•状态：Mock/替代实现。鉴权、可见性、状态检查和 SSE 传输为真实代码；正文来自固定联调 JSON，不调用测肤算法、RAG 或 AI。

•限制：仅非生产环境；无 Last-Event-ID、持久化、重放、断点续传和取消 API。客户端断开只停止本次传输，不取消已经受理的测肤分析。

5. 端到端流程

5.1 测肤、报告播报与聊天

云台上传三视角照片
  → POST /api/v1/skin-assessment-tasks（M3-A01）
  → PG skin_assessments + async_jobs
  → Python Worker
  → 测肤 provider（当前 double）
  → 报告写入 PG并进入 report_ready
  → GET /api/v1/skin-assessment-tasks/{taskId}/report-narration-stream（M3-A07）
  → start / text_delta×2 / done
  → 云台按文本块组句
  → 设备端逐句 TTS
  → 播报完成后进入文本聊天

停止播报时，设备关闭 SSE 连接并清空本地 TTS 队列。这个动作不会撤销已经受理的测肤任务，也不会要求服务端取消分析。由于当前没有 Last-Event-ID，断线重连不得自动再次朗读客户端已经确认播放的句子；客户端应保存本地播放水位，重新请求后丢弃已播内容，或回到报告页让用户主动重播。

5.2 云台文本追问

云台文本
  → POST /api/v1/gimbal-ai/messages（M2-A09）
  → Java 鉴权/校验
  → llm-rag SSE
  → Java 白名单重编码并逐事件 flush
  → 云台显示文本

这条路径目前是无上下文文本问答。报告播报结束可以进入聊天界面，但后端不会自动把报告上下文带入 M2-A09。

5.3 报告到 AI 方案

测肤报告 JSON
  → Python Worker plan.generate
  → llm-rag AI 方案 API
  → 严格映射与代次校验
  → care_plans 写入 PG

当前 adapter/service 已实现但待完整 E2E；测肤报告输入仍来自 mock provider。方案成员归属、参数白名单、N 和输入代次由服务端校验，不能把模型任意 JSON 直接发布为 ready。

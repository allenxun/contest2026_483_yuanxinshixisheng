# openVela 配网检查

护肤卡片跳转 OpenVelaConnectActivity。页面搜索名称包含 openVela 的 BLE 设备，连接后显示连接 Wi-Fi 按钮。

已调整：步骤说明、白色卡片、按钮边距、触控尺寸、信号文字对比度；扫描/配网请求互斥；断连复位；空列表与超时重试；UTF-8 凭据传输；密码不输出发送日志；分包任一发送失败不能算全部成功。只有收到设备结果才显示 Wi-Fi 成功，成功后断开 BLE 不撤销成功页面。

## 当前实现的协议（需要固件确认）

- 扫描指令：ASCII 字符 `1`，字节 `0x31`，不带换行。用户已确认 ASCII。
- 返回列表：`{"cmd":"wifi_list","list":[{"ssid":"网络名称","rssi":-40}]}`；兼容直接 JSON 数组及已有字段别名。RSSI 按 dBm 展示、排序，同名保留最强信号。
- 提交：UTF-8 `{"cmd":"wifi_connect","ssid":"网络名称","pwd":"密码"}\n`，沿用项目原有字段定义。
- 结果：`{"cmd":"wifi_result","code":0}` 表示成功；沿用旧实现对纯文本 `1/ok/success/true` 成功、`0/fail/false` 失败的支持。只有正在连接时才接收结果。
- 支持以换行结尾的分包消息，也支持完整 JSON 或已识别单值不带换行的消息。连续多条无分隔消息不属于已确认支持的协议。

## 尚需联调确认

1. 固件的服务 UUID、写入 UUID、通知 UUID。现有 BleManager 会尝试所有可写特征，不能在没有 UUID 的情况下保证只发送到正确通道。
2. Wi-Fi 列表字段/分包规则、凭据结构和成功/失败返回值。
3. 固件请求编号：没有请求编号时无法可靠区分超时后的旧响应与下一次请求。
4. 用真机测试中文 SSID、长列表分包、错误密码、空列表、设备掉电和配网成功。当前环境未完成硬件联调或屏幕视觉验收。

通知订阅已补齐：openVela 连接必须等 CCCD 0x2902 写入成功才报告就绪；同时支持 Notify/Indicate，失败及超时反馈给页面。旧 GATT 的通知、服务和写回调不再影响新连接。BLE 广播由 ScanCallback 接收，仅用于发现设备。

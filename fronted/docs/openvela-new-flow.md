# openVela 新测肤与蓝牙护理流程

入口：我的 → openVela 测肤列表 → 人员 → 测肤记录 → 报告 → 查看方案 → 护肤方案。
四个 Activity 均为新增页面，位于 ui/openvela；不调用旧护理执行接口。

## 数据与接口替换点

OpenVelaData 当前是明确标识的演示数据，人员与报告用 ID 关联并校验。
后端就绪后替换该仓库的方法，可参照现有 faces、faces/{faceId}/reports、
faces/{faceId}/reports/{reportId} 接口结构。新方案接口尚未确认，不使用蓝牙 MAC 伪造数据库设备 ID。
演示方案不向设备发送真实强度、时长等参数。

## 占位设备协议

全部是单个 ASCII 字符，无换行；OpenVelaCommands 集中维护：

| 指令 | 含义 |
|---|---|
| a | 蓝牙连接并订阅成功后初始化 |
| b | 用户确认后开始工作 |
| c | 停止工作 |
| d | 查询工作状态，重连时自动发送 |

回复暂定 UTF-8 文本 ready / running / stopped / completed / error，
建议每条结尾带换行，也支持单独完整单值回复。不把普通 ok 或 GATT 写入回调当成设备工作状态。
通知确认前开始按钮不可用；回复超时 10 秒进入状态未确认，不自动重发开始。
新方案仅 BLE，旧设备配网页仍用 ASCII 1 请求 Wi-Fi 列表。

## 搜索与传输

搜索只匹配 openVela 名称，按地址去重，最多 5 台、最长 30 秒。
连接时停止扫描，服务发现及通知订阅完成后关闭弹窗，再发送初始化或状态查询。
共享 BleManager 串行遍历所有可写特征，全部通道/全部分包成功才返回发送成功；有响应写等回调，无响应写只能确认系统接受。
固件必须保证重复开始不会重复执行/重置计时；正式协议建议添加请求 ID 去重。

## 工作异常与退出

- 断连保留设备可能工作状态，禁止再次开始；重连仅允许原设备，先查询状态。
- 工作时返回：继续护理 / 停止并退出；收到 stopped/completed 后才自动退出。
- 停止失败、10 秒无响应：留在页面 / 重试停止 / 仍然退出，并告知可能继续工作。
- Activity 重建使用应用级会话，App 被杀后读取未确认记录并要求重连查询。
- 已确认停止/完成才清除未确认标记，最近一次确认结果保存本地；没有真实后端执行记录接口。
- 手机不能保证强杀时发出停止，设备固件仍需实现最长工作时长、独立停止能力。这部分不是 Android 能替代的。

## 验收

使用新入口依次进入四页，返回检查人员/报告不串数据。
用固件测试 30 秒无设备、超过 5 台、同设备重复广播、连接失败、通知订阅失败；
a 后回复 ready，b 后回复 running，c 后回复 stopped，完成回复 completed。
测试每个阶段断连、停止无回应、工作中返回、旋转/后台再进入、强杀后重开。
当前验证：新页面、会话、共享蓝牙及隐私依赖已通过缓存 Kotlin 编译器的独立编译。
完整 APK 构建受本地 SDK 36.1 文件缺失阻塞，未完成真机视觉验收或固件联调。

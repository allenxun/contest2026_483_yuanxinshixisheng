## 现在前端可以测试什么

连接 **VelaVision K7**；服务 `6b7a0001-78c3-4f2e-9c2f-3ecbc2d74680`，手机发送 Write 为 `6b7a0002-78c3-4f2e-9c2f-3ecbc2d74680`，手机接收 Notify 为 `6b7a0003-78c3-4f2e-9c2f-3ecbc2d74680`。每次重连重新订阅 Notify。

1. 未联网扫描阶段发送 X，按行收集 Wi-Fi 列表直到 scan_done；不能把一次 Notify 当成完整 JSON 或整个列表。
2. 使用同目录适配器的 submitCredentials() 提交 SSID 和密码，按 [信息接收联调说明](信息接收联调说明.md) 的分包与事务 ID 处理。
3. 收到 OK/已收到只代表格式有效且设备已接收，密码随后擦除，stored:false；不能显示“已联网”，不能据此证明密码正确。

当前原生 Wi-Fi 在线时 X 会返回 scan_failed/detail -16，尚不支持在线扫描。由设备端明确切换到未联网扫描阶段后再测试，不能把这个错误当作蓝牙异常。最新状态快照为 Wi-Fi 在线、手机 BLE 未连接；状态会随现场操作变化。

## 真正联网联调还需要的设备端接口

- 将 BLE 凭据请求交给已有原生 WPA2/DHCP 工作线程，避免在蓝牙收包回调中等待认证。
- 完成完整密码提交、规则与事务 ID；通过请求 ID 关联联网中、成功和失败回包，成功带真实 IP，失败带明确错误码。
- 将 status 绑定真实原生网络状态；目前 BLE status 的 wifi_connected:false/ip:null 仍为旧信息接收阶段实现。
- 对端到端 App 成功联网、错误密码、超时/断连进行真机回归，再将 connect 改为 true。不能仅修改能力标志。

尚未开放上述接口，不建议前端现在启用“确认后自动联网成功”的流程。设备端原生认证/IP 诊断已实测，可作为接入基础。

# 现在开始蓝牙双向收发测试

**新版真实联网入口：** 使用 [真实联网联调说明](真实联网联调说明_20260909.md) 和 `完整配网接入示例.mjs`，调用 `connectWifi()`。旧 `submitCredentials()`/OK 仅表示收到信息。可转发 `../deliveries/前端真实联网联调_20260909.zip`。


板端已启动，名称 **VelaVision K7**。本轮只测消息往返，不要求 Wi-Fi 真正联网。请从 Android/iOS App 连接并发现 GATT 服务，系统蓝牙页面“已配对”不代表已经打开业务通道。

1. 使用本目录 `vela-provision.mjs` 连接，等待 `ble.connect(deviceId)` 成功；适配器会订阅通知并检查加密状态。
2. 调用 `ble.scan()`，它发送单字节 `X`。板端返回 `scan_started`、多条 `ap` 和 `scan_done`。收到列表即可证明板端向前端发送成功。不是连接后自动推送。
3. 选择一条记录，把它的 `ssid_b64` 原样提交：

```js
const receipt = await ble.submitCredentials({
  ssid_b64: selectedAccessPoint.ssid_b64,
  password: 'EXAMPLE_ONLY_123'
});
```

这里先使用测试密码，不必用真实网络密码。密码须为 8..63 个可打印 ASCII 字符。

4. 收到下面的回包，显示 **“OK，设备已收到”**：

```json
{"v":1,"id":103,"session":1,"event":"credentials_received","validated":true,"stored":false,"wifi_connected":false,"ip":null}
```

`id` 对应本次提交，`session` 对应本次 BLE 会话，实际值不一定是示例中的数字。这个回包表示板端收到并通过格式校验；不会真正联网，密码校验后即清除。

设备能力应包含 `receive_credentials:true`、`connect:false`。不要调用 `connectWifi()`；发送普通聊天文字或裸 `OK` 也不是当前协议。

## 怎么核对板端确实收到

电脑端已启动一次最多 30 分钟的串口观察，只记录连接和处理结果。日志位置：

`E:\openvela\VelaVision\evidence\credentials-20260909\frontend-live-observation-01.jsonl`

例如 `PROV command=4 id=103 ret=0 notify_ret=0` 表示设备处理了提交并把回复交给蓝牙发送；**前端实际收到上述业务回包，才算双向闭环通过**。日志不显示密码。

当前已有 Windows BLE 客户端真机验证：真实列表含 Lansee、提交测试信息成功、非法密码拒绝。Android/iOS 前端本次是否通过，须以你们现场实际收发为准，尚不能代填成功。

完整 UUID、分包、错误码与示例见 [信息接收联调说明](信息接收联调说明.md)。三个 `.mjs` 文件均在同目录。

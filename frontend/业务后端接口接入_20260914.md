# 前端业务后端接口接入（2026-09-14）

实现文件为 `gimbal-cloud-client.mjs`，直接沿用当前前端的 ES Module 形式，不依赖 npm 包。构造函数接收 `fetchImpl`，可用于浏览器、支持 Fetch 的 App 容器和 Node 联调环境。

## 状态边界

BLE 收到板端 `wifi_connected:true` 和有效 IP 后，页面可以显示“Wi-Fi 已连接”。业务后端没有“由 APP 把设备强制改为在线”的接口。云端在线状态必须由 K7 使用设备会话调用心跳推进，APP 再读取 `GET /api/v1/gimbals/{gimbalId}/status`。只有 `connectionStatus=online` 且 `isStale=false` 才显示“云端已连接”。

联网后的顺序为：

1. 前端通过 `VelaProvision.connectWifi()` 完成 BLE 配网并显示真实 IP。
2. K7 用预置的 `credential/credentialVersion/proof` 调用 `createGimbalSession()`，会话 token 仅保存在内存。
3. K7 调用 `heartbeat()`；`accepted=true` 表示本次观察推进成功。
4. APP 使用自己的 Bearer token 调用 `getGimbalStatus()`，确认在线投影后开放云端业务入口。
5. ASR/TTS 继续按独立语音合同接入。当前 OpenAPI 没有语音端点，本客户端没有伪造对应方法。

## 已封装端点

- 设备会话：`createGimbalSession()`
- 心跳和状态：`heartbeat()`、`getGimbalStatus()`
- 绑定：`getBindingStatus()`、`bindGimbal()`、`unbindGimbal()`
- 当前测肤任务：`getCurrentAssessment()`
- 新建与补拍：`createAssessment()`、`retakeAssessment()`
- 任务、报告与媒体：`getAssessment()`、`getReport()`、`getMedia()`

客户端自动处理 Bearer、`Idempotency-Key`、JSON 成功/错误信封、`Retry-After`、`X-Request-Id` 和媒体二进制。JSON 方法保留 `{requestId,data,meta}` 完整成功信封，因此调用方能判断 `meta.replayed`；媒体方法返回 `{body,contentType,requestId}`。所有 bigint/revision/seq 都保留为十进制字符串。multipart 的 `metadata` 使用 `application/json` Blob，图片集合在发送前校验。

## 使用示例

`业务后端接入示例.mjs` 展示两个前端入口：

- `reconcileConnectedState()`：BLE 配网完成后显示本地联网，并读取后端在线投影。
- `submitAssessment()`：用三视角 Blob 创建异步测肤任务。

开发地址目前是 `http://10.3.3.170:18085`，只适合局域网联调。生产前必须替换为冻结的 HTTPS 域名并通过证书校验。APP token 来自 APP 登录，K7 设备凭据只属于 K7；MiMo key 只属于服务端安全配置，均不得写入前端代码、日志或持久化存储。

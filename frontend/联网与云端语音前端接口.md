# 前端联网与云端语音对接接口

前端继续使用现有 BLE v1 协议和 `vela-provision.mjs`，不增加新的板端命令。`整机联网语音适配器.mjs` 只在 App 内编排已有的扫描、`connect`、`wifi_connecting`、`wifi_connected` 和 `status`，并把局域网、互联网、云端语音三个状态分开。

## 调用流程

```js
import { VelaOnlineSpeechAdapter } from './整机联网语音适配器.mjs';

const adapter = new VelaOnlineSpeechAdapter(uni, {
  onState: state => render(state),
  internetProbe: async ({ ip }) => api.checkInternet({ ip }),
  reportOnline: async state => api.reportDeviceOnline(state),
  cloudProbe: async () => api.checkSpeechService(),
  speechClient: {
    asr: (audio, options) => api.asr(audio, options),
    tts: (text, options) => api.tts(text, options)
  }
});

await adapter.open(deviceId);
await adapter.scan();
adapter.selectNetwork(selected.ssid_b64);
await adapter.connectSelected(passwordInput, () => clearPasswordInput());
```

前端收到的状态字段：

| 字段 | 含义 |
| --- | --- |
| `bluetooth_ready` | BLE 已连接、GATT 已发现且链路已加密 |
| `scan_done` / `networks` | 收到同一次扫描的完整列表；网络选择必须来自该列表的原始 `ssid_b64` |
| `wifi_connecting` | 板端已开始认证/DHCP |
| `wifi_connected` / `ip` | 板端回报真实 DHCP 地址，只证明加入局域网 |
| `internet_ready` | App 注入的本次 K7 链路互联网证据探针成功；手机自身可达不能代替 |
| `online_reported` | 已向业务后端回报 `{wifi_connected:true, ip, internet_ready:true}` |
| `cloud_ready` | App 注入的云端语音探针成功，可以调用 `asr()` / `tts()` |

只有 `cloud_ready:true` 才开放云端 ASR/TTS。联网成功后可先播放板内固定的“联网成功”，避免云端还未就绪时没有反馈；随后再切换到云端语音。

## 音频边界

- K7 到后端的批量 ASR：WAV 容器，PCM S16LE、16 kHz、单声道。
- 流式 ASR：原始 PCM S16LE、16 kHz、单声道，20 ms 一包（640 字节），流开始时单独发送格式元数据和序号/时间戳/结束标记；不要给每个分片套 WAV 头。
- 云端 TTS 当前返回 24 kHz、单声道、16 bit WAV。建议业务后端解码并重采样为 K7 可直接播放的 PCM S16LE、16 kHz、单声道；流式输出 20 ms 一包（640 字节）。

`speechClient` 应调用业务后端代理，不在手机前端或固件中保存小米 Token Plan 密钥。当前业务 OpenAPI 尚无 ASR/TTS 路径，后端补齐接口前 `cloudProbe` 必须返回 false，前端不能显示云端语音已就绪。

## 主机/后端语音桥 HTTP 契约

`speech-http-client.mjs` 和 `整机BLE与云端语音拼接示例.mjs` 使用以下最小接口。这里的路径属于待部署的主机/后端语音桥，不冒充现有业务 OpenAPI 已经提供这些路径。

| 请求 | 请求体 | 成功响应 |
| --- | --- | --- |
| `GET /health` | 无 | JSON：`{"ready":true,"asr":true,"tts":true}` |
| `POST /v1/asr` | `Content-Type: audio/wav`，16 kHz/单声道/PCM S16LE WAV 原始字节 | JSON：`{"text":"识别文字"}` |
| `POST /v1/tts` | JSON：`{"text":"联网成功","format":"wav","sample_rate":16000,"channels":1,"voice":"白桦"}` | 16 kHz/单声道/PCM S16LE WAV 原始字节 |

客户端会检查 ASR 输入和 TTS 输出的 RIFF/WAVE、PCM 编码、声道、采样率和位深。超时返回 `request_timeout`，网络失败返回 `network_error`，非 2xx 返回 `http_error` 并保留数值 `status`；不读取或回显错误响应正文。`401/403` 等鉴权问题由语音桥内部处理，前端请求没有 `Authorization` 字段。

## 密码处理

适配器只把密码作为局部参数直接传给既有 `connectWifi()`。状态回调、联网回报和错误回报均不包含密码；请求结束后调用页面提供的 `clearPasswordInput()`。前端不得记录 BLE 原始 `connect` JSON、密码或完整 ATT 写入内容。


## 2026-09-14 异步状态修复

适配器现以链路代次和探测代次丢弃 BLE 断开、dispose、重复探测之后迟到的异步结果。重查期间先关闭互联网/云语音门禁；真实 `VelaProvision.status()` 返回断网、IP 改变或请求失败时撤销旧联网状态。请在页面定时检查中调用 `refreshConnectivity()`；当前 BLE 协议尚无已验证的长期断网推送，因此这不是持续在线监控的真机验收。

`createWholeDeviceClient()` 新参数 `probeDeviceInternet` 默认返回 false。后端或板端必须提供当前 K7 网络链路的真实互联网证据；仅 `/health` 从手机可达不能置 `internet_ready`。该示例的 ASR/TTS 客户端运行在 App 中，不能据此宣称板端八门禁和音频路径已经完成。

对注入的 `provision`，适配器也会订阅其 `onConnection`/`onWifiState` 并保留已有回调；该实例应由单个适配器持有。BLE 断开后需重新 open/scan/select，旧选择不会跨设备保留。

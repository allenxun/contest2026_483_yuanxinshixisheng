# 手机调试器操作卡：X 扫描 → 提交信息 → OK

**最新（20:17）：真实联网接口已接通并 RAM 上板验证，可以开始功能联调。** 使用新版 `connectWifi()`，见 [真实联网操作说明](真实联网联调说明_20260909.md)。旧 submitCredentials/OK 仍只表示已收到。下文旧 connect:false 及稳定性记录是历史阶段，不代表新接口尚未实现；新固件尚未通过长期稳定性验收。

当前 RAM 固件为 `wifi-amsdu-index-20260909`。30 分钟保持和 10 次手机重连/列表回传已完成，但测试后发现 BLE 超时异常，尚未正式稳定验收。前端仍只接收信息、`connect:false`；原生 Wi-Fi 在线时不能发 X 扫描。见 [最新实测与边界](无线稳定性与重连实测_20260909.md)。UUID 保持一致。

设备程序已运行，名称 **VelaVision K7**。本轮只接收并校验 Wi-Fi 信息，回复“已收到”；不保存密码、不尝试连接路由器。

## 1. 选择正确的蓝牙特征

在 App 能列出服务和特征的页面中选择以下项目。仅在聊天框看到“已连接”还不够；要指定发送特征和接收通知特征。

| 用途 | 完整 UUID |
| --- | --- |
| 自定义服务 | `6b7a0001-78c3-4f2e-9c2f-3ecbc2d74680` |
| 接收：Notify，开启通知 | `6b7a0003-78c3-4f2e-9c2f-3ecbc2d74680` |
| 发送：Write，带响应写入 | `6b7a0002-78c3-4f2e-9c2f-3ecbc2d74680` |

Notify 是手机订阅板端回复的通道；Write 是手机向板端发命令的通道。它们不是要输入聊天框的文字。每次重新连接都要重新开启 Notify。

只选择或填入 Notify UUID 不一定会启用订阅，还要执行 App 的“开启通知/订阅”操作。若页面支持查看描述符，Notify 下的 `0x2902`（CCCD）值应为 `01 00`；仅写描述符不一定会注册 App 的接收回调，优先使用 App 的通知开关。前端使用 `notifyBLECharacteristicValueChange({deviceId,serviceId,characteristicId,state:true})`，其中 characteristicId 为 Notify UUID；现有适配器已自动调用。

现场若板端显示 `connected=1 subscribed=0 commands=0`，说明链路存在但通知尚未启用，X 未进入业务处理。应先解决订阅，不要连续发送 X。

## 2. 发送 X，接收真实 Wi-Fi 列表

先开启 Notify，再向 Write 发送一个大写 `X`。文本模式不附加换行；若选择 HEX 模式，只发送 `58`。关闭自动重发，发一次并等待。

板端先发 `scan_started`，再逐条发 `ap`，最后发 `scan_done`。这些是换行分隔的 JSON，可能分成多个通知片段，看到半段内容应继续接收和拼接。前端需要等到 `scan_done` 才认为列表接收完整，最长等待 60 秒。

例如扫描行中的 `ssid_b64:"TGFuc2Vl"` 对应显示名称 Lansee。显示时可解码，提交时保留扫描行原来的 `ssid_b64`。

## 3. 提交网络信息，接收 OK 回执

下面是使用测试密码的命令。末尾必须是实际 LF 字节 `0A`，不能输入两个字符反斜杠和 n：

```json
{"v":1,"id":103,"cmd":"submit_credentials","ssid_b64":"TGFuc2Vl","password":"EXAMPLE_ONLY_123"}
```

板端每次 Write 接受最多 20 字节，整条命令必须在首片到达后 10 秒内发完。若调试器支持自动分包，设为每片最多 20 字节并使用带响应写入。也可参考同目录 `手机调试HEX分包.txt` 的 5 个片段，顺序发送，最后一片已包含 LF；手动操作若无法在 10 秒内完成，应由前端适配器发送。不要把整条 JSON 一次写入，也不要自动重发。

收到类似以下完整回包才表示本次提交成功；`session` 是动态值，`id` 应与提交一致：

```json
{"v":1,"id":103,"session":1,"event":"credentials_received","validated":true,"stored":false,"wifi_connected":false,"ip":null}
```

前端把 `credentials_received` 显示成 **“OK，设备已收到”**。当前回包是 JSON，不是裸字符串 OK；不要显示“Wi-Fi 已连接”。

密码规则：8..63 个可打印 ASCII 字节，保留首尾空格及反斜杠，不自动 trim。此次只验证格式和信息接收，无法证明路由器密码正确。不要分享真实密码的调试截图或日志。

## 4. 前端 App 直接调用

同目录 `vela-provision.mjs` 已完成通知订阅、分包和通知组包，无需手工操作 HEX：

```js
const capabilities = await ble.connect(deviceId); // 自动订阅 Notify
const result = await ble.scan();                 // 内部发送 X
const receipt = await ble.submitCredentials({
  ssid_b64: selectedAccessPoint.ssid_b64,
  password: passwordInput
});
// receipt.event === 'credentials_received' → 显示“OK，设备已收到”。
```

启用提交按钮看 `receive_credentials:true`。`connect:false` 表示真实联网未开放，不妨碍本轮发送信息。完整初始化代码、错误处理及 API 见 `前端蓝牙联调操作手册.md`。

验收需分别确认：手机收到扫描列表、板端收到提交、手机收到匹配的成功回包。连接稳定不等于业务收发已经通过。

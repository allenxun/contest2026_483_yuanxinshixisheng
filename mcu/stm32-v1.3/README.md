# VelaVision STM32F103RCT6 v1.3：X 轴复位到行程中间

2026-09-07。基于用户已经烧录并测试过的 v1.2 硬件 PWM 工程创建独立副本。用户要求只调整 X 复位位置，Y 保持现状。本包已编译，尚未烧录和实机验证。

## 修改结果

| 项目 | v1.2 | v1.3 |
|---|---|---|
| X 上电/复位脉宽 | 712µs | 1492µs |
| X 命令映射 | clamp(712 + (-12*x)/10, 500, 2500) | clamp(1492 + (-12*x)/10, 500, 2500) |
| Y 上电/复位脉宽 | 700µs | 700µs，保持不变 |
| Y 命令映射 | clamp(700 + (15*y)/10, 500, 2300) | 完全相同 |
| PWM | TIM2 双通道硬件 PWM，50Hz | 保留 |
| UART 协议、方向和比例 | v1.2 配置 | 保留 |

相对 v1.2 仅修改 `firmware/BSP/bsp_servo.c` 的 X `.pwm`、`.MIDPWM`（均为 1492），以及 `firmware/USER/main.c` 的版本号。Y 结构体、启动路径、串口接收和主循环均保持原代码。原始 D 盘项目、v1.2 副本和 K7 eMMC 未修改。

1492 来自本次用户标定的 A/D 两端脉宽平均值：(2452 + 532) / 2。它是所选脉宽范围的中点，尚不能当作已测量的机械角度中点，也不代表已验证 270° 行程。

## 新旧控制坐标

| 位置 | 旧 X 命令 | 新 X 命令 | 脉宽 |
|---|---:|---:|---:|
| A 侧记录边界 | -1450 | -800 | 2452µs |
| A/D 中间 | -650 | 0 | 1492µs |
| D 侧记录边界 | 150 | 800 | 532µs |

所以新控制器应使用 X=-800…800，复位参考 X=0。上述数值是控制单位，不是角度。旧坐标加 650 可换算为新坐标；任意整数值跨过零点时，因 C 整数除法向零截断，可能有 1µs 差异，表内数值完全一致。

Y 不重新标定：原记录范围 -120…975 保留，上电命令仍为 Y=0（700µs）；原记录的视觉参考 Y=25 也不等于新的上电设置。本版没有把 Y 中位移到行程中间。

改变电气中位后，X 上电姿态会相对以前转动，这是本次要求的调整。照片中旧复位朝向不能与新的行程中间自动等同；无需为此改动摄像头固定结构。

## Keil 编译与烧录

1. 先退出旧的标定/跟随控制程序，避免旧 X 坐标继续发往 MCU。
2. 用 Keil5 打开 `firmware/USER/steer_freeII.uvprojx`，目标 `steer_free_II`，编译器 ARMCC 5.06。
3. 本包已生成 `firmware/OBJ/stree_free_ii.hex` 和 `.bin`，链接起始地址 0x08000000。沿用此前成功的 Keil 烧录方式。
4. 烧录后先观察 MCU 单独复位：X 转到新中间，Y 保持原复位行为。此时先不要启动旧 K7 标定程序；等匹配 v1.3 的 X 范围/显示映射部署后再跟随。

`k7-coordinate-profile.json` 是配套坐标说明，尚未安装到 K7，也不能直接替换旧 calibration.json。旧程序含硬编码的 X 边界和 712µs 显示基准，需要同步修改；否则可能继续限幅，或显示错误的脉宽。

## 验证记录

- Keil 全量编译：0 errors、56 warnings，详见 `keil-build.log`。警告来自保留的旧模块，包含未启用 PS2 路径的数组越界警告；本次未修复这些旧模块。
- `test_variant.py` 提取当前真实限幅、映射和串口函数：验证 X=0 为 1492µs，X=±800 为原两端脉宽；遍历全部 65536 个 int16 Y 指令确认输出不变；串口分片、噪声、缓冲区、临界区回归通过。
- `baseline-v1.2-sha256.json` / `changes-from-v1.2.patch` 记录源代码差异；`release-sha256.txt` 标识本次新二进制。
- 电脑测试的寄存器使用桩函数；不替代上板验证。本包不代表实时跟踪已完成验收，也没有新增位置反馈。

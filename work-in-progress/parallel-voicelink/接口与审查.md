# VoiceLink 主机候选接口与审查

此目录供主会话评审后集成；没有连接任何设备，没有 openvela 构建或运行结论。

## 网络状态机

`WaitingWake → ScanningWifi → WaitingNetworkChoice → EnteringPassword → CredentialsReceived → ConnectingWifi → Completed`。

开放网络跳过密码输入，但实际端口尚未支持时必须返回 Unsupported。连接端口可以跳过中间阶段，直接报告最终结果；**CredentialsReceived、Connecting 均不能触发成功播报**。没有保留旧同步 `ConnectStatus::Ok` 接口，以使旧平台适配器在迁移时明确编译失败，避免误接。

| 调用/事件 | 契约与行为 |
| --- | --- |
| `beginConnect(ssid, password, length)` | 有界、非阻塞、noexcept；接受或拒绝都返回本端口生命周期内唯一的非零 uint64 ID。SSID/密码指针仅调用期间有效，异步服务需在返回前复制所需内容。不能回调 Controller。 |
| `CredentialsReceived` | 仅表示已接收；控制器擦除本地密码，等待后续结果。 |
| `Connecting` | 认证/DHCP 进行中；重复事件不重复播报；迟到的接收事件不倒退状态。 |
| `pollConnect(id)` | 返回该事务的最近状态；控制器忽略其他 ID。真实端口不要从公共队列消费其他客户端事件。 |
| `IpReady + ipv4` | 端口仅在目标网络认证及 IP 配置完成后发出。控制器做 IPv4 格式和明显无效地址检查；它不能自行证明地址确实来自硬件。Completed 表示配网 IP 就绪，不证明网关/DNS/互联网可达。 |
| WrongPassword/Failed/NetworkNotFound/Busy/Unsupported/Timeout | 不成功；保留网络选择、清除密码并提示重试。Cancelled 进入 Idle。Unsupported 可通过“重新选择网络”回到扫描。 |
| `ClockPort::nowMs()` / `Controller::poll()` | 单调 uint64 毫秒计时，默认超时 30000 ms。恰好到达期限时超时优先。应用必须调度 poll，不能等阻塞 ASR 返回才检查。 |
| `cancelConnect(id)` | 幂等、noexcept、有界；仅取消指定事务并擦除其凭据，不可断开 BLE 或其他调用方拥有的连接。失败终态可能再次收到 cancel，必须安全。 |
| 成功终态 | 服务在报告 IpReady 前释放事务凭据/临时资源；控制器清除活动 ID，不调用 disconnect。后续链路掉线监测是板端服务职责。 |

Controller 所有方法在一个任务线程串行调用。ASR、TTS、真实网络工作在各自的工作任务上，通过消息交回；建议控制器每 50 ms 内获得一次 poll 调度。现有同步 `scan()` 沿用原始接口，扫描超时/在线拒绝由端口明确返回非 Ok；本轮没有实现异步扫描调度器。TtsPort 应用失败状态报告错误；启用 C++ 异常时，控制器也捕获 speak/stop 异常并转入 Error、清理密码及事务；禁用异常时仍需端口返回失败；应用必须给扫描/播报安排有界执行，否则不能保证墙钟超时精度。

析构、reset、用户取消、EOF、FatalError、TTS 返回失败或抛异常时取消待决事务并擦除密码。密码缓存预留容量，清空时不 shrink，避免逐字增长过程中产生未擦除的旧分配；删除位置置零，最大网络数限制为五以匹配原播报数组。上游 ASR 字符串和服务复制的密码仍由各自所有者擦除；本实现不能清除外部字符串或系统历史副本。密码不能进入 Agent、日志或 TTS。

## 音频/API 固定版本

核对并保存的是 [sherpa-onnx v1.12.14 官方 C API](https://github.com/k2-fsa/sherpa-onnx/blob/26aa2fa93210376a89de3a65a1a4dd320c37f5e9/sherpa-onnx/c-api/c-api.h)，commit `26aa2fa93210376a89de3a65a1a4dd320c37f5e9`。`vendor/sherpa-onnx/version-lock.json` 固定提交及文件 SHA-256；头文件、LICENSE 均从官方获取，并再次按提交核对内容。选定该版本用于接口准备，不代表推荐最新版本。未下载运行库或模型，未选择/验收 ONNX Runtime 版本。

原输入 `speech_engine_k7.cpp` 中的构造/流函数名称及部分配置成员与该版本不符。候选 `SpeechSession` 使用官方头文件声明的创建/销毁、AcceptWaveform、IsReady、Decode、InputFinished 和结果获取接口。配置由调用方传入：特征采样率/维度需明确设置；端点字段在 recognizer config 的平铺 `rule1_min_trailing_silence` 等成员；规则文件使用 TTS config 的 `rule_fsts`/`rule_fars`，不是 VITS 子结构的 `tts_rule_fsts`；sid、speed 是生成调用参数，输出采样率取生成音频。实际模型路径和配置有效性仍需真实运行库验证。

| 原输入问题 | 候选处理/剩余工作 |
| --- | --- |
| 将 float samples 赋给 int16_t 指针 | 明确乘 32768、四舍五入、夹紧至 [-32768,32767]；NaN→0，正负无穷分别饱和。PCM16→float 除 32768。 |
| 只按整样本累计 write，零返回可能死循环 | 明确 PCM16 小端字节流，保存奇数字节短写的偏移；0、负数、超长返回均终止，不忙重试。驱动自身负责 EINTR/EAGAIN 与限时等待。 |
| 非空但无有效数据的生成结果泄漏 | RAII 销毁所有非空 GeneratedAudio，包括 samples 空、n≤0、非法采样率及设备打开失败路径。 |
| 忽略 ioctl 返回值、未完整配置结构 | 本轮去掉具体设备假设。PcmSink.begin 必须检查每个板端配置/启动结果，失败时自行释放部分打开资源；成功后保证调用 end。实际 NuttX PCM/消息队列接口尚未实现。 |
| 接收音频但不持续运行解码 | 每批转换后 while IsReady 解码；InputFinished 后继续 drain，再取结果。feed 每次最多512个完整 PCM16 样本；奇数录音字节必须由采集适配器缓存到下一次。 |
| 单次 decode 未必得到最终文本 | 测试每批产生3步、结束产生2步；确认所有步骤完成后才取结果。模型所需尾部静音长度未假定，应按选定模型另行验证。 |
| 全局资源无完整退出路径/volatile stop 非线程同步 | SpeechSession 拥有 TTS、recognizer、stream；销毁顺序 stream→recognizer→TTS，结果另有 RAII。stop 使用 atomic_bool。 |

单次 drain 的默认预算1024步，用于避免故障替身无限 ready；它不是模型推荐阈值或真实推理超时。feed 遇到非法参数、Cancelled/DecodeLimit 时立即释放旧流；后续 feed/finish 均被拒绝，必须 beginStream 创建新一轮，错误不能变成识别完成。finish 在任何退出路径均释放流，重复 finish/feed 被拒绝。

同步 `SherpaOnnxOfflineTtsGenerate` 内部不能被此 stop 标志抢占，取消只在进入/返回生成调用与写入批次之间生效；单次真实 Decode 同样不能抢占。长期运行与硬实时取消需要生成回调/工作任务、实际运行库和有界音频驱动配合，未验收。SpeechSession 使用单所有者线程；不能并发 init/close/feed/speak。全双工/抢麦、重采样、模型加载内存峰值、实际音频设备均留给后续板端集成。

## First native build gate, then actual model gate

1. **Port and compile ORT onnxruntime_common first**, using the real NuttX AArch64 toolchain/generated headers/C++ ABI. This target contains Env/platform and exposes portability failures before all CPU kernels are compiled. Source [onnxruntime_common.cmake](https://github.com/microsoft/onnxruntime/blob/8f5c79cb63f09ef1302e85081093a3fe4da1bc7d/cmake/onnxruntime_common.cmake) chooses generic POSIX for non-Windows; it does not implement NuttX. Add an explicit platform source-selection branch, not a `Linux` system-name disguise. Compile then link a small native platform test for owned regular-file read/seek/size, aligned allocation/free, monotonic sleep, pthread create/join. It is a prerequisite, not model inference.
2. Build ORT CPU libraries/session/C API after that gate. CMake入口 `cmake -S <ort>/cmake -B <new-build> -DCMAKE_TOOLCHAIN_FILE=<reviewed-nuttx.cmake>`; ORT root requires CMake>=3.26/C++17. Candidate flags: BUILD_SHARED_LIB=OFF, BUILD_UNIT_TESTS=OFF, ENABLE_PYTHON=OFF, USE_CUDA=OFF, USE_RKNPU=OFF, USE_NEURAL_SPEED=OFF, ENABLE_CPUINFO=OFF (all prefixed `onnxruntime_`). Crucially **MINIMAL_BUILD=OFF** for existing .onnx models; upstream minimal supports ORT format only. Keep exceptions enabled for initial full ONNX path: this version documents disabling exceptions only with minimal build. Do not disable contrib/quantization ops until actual graph closure is checked. These options narrow scope but do not complete the platform port. See [ORT root](https://github.com/microsoft/onnxruntime/blob/8f5c79cb63f09ef1302e85081093a3fe4da1bc7d/cmake/CMakeLists.txt).
3. Add **native C API create/release Env and SessionOptions** executable linked against complete ORT static dependency closure (not common alone), then a tiny known ONNX CPU graph in board RAM to validate session/run/cleanup. Inspect undefined symbols, target arch and link map. Do not claim this is ASR. Static ORT normally comprises multiple archives; one archive name or a Linux ABI link success is insufficient.
4. Build sherpa **sherpa-onnx-c-api** static target (its dependency is sherpa-onnx-core). First ASR-only: BUILD_SHARED_LIBS=OFF, SHERPA_ONNX_ENABLE_C_API=ON, ENABLE_TTS=OFF, ENABLE_BINARY=OFF, BUILD_C_API_EXAMPLES=OFF, ENABLE_PORTAUDIO=OFF, ENABLE_WEBSOCKET=OFF, ENABLE_PYTHON=OFF, ENABLE_JNI=OFF, ENABLE_SPEAKER_DIARIZATION=OFF, ENABLE_GPU=OFF, ENABLE_RKNN=OFF (unqualified ENABLE names here carry SHERPA_ONNX_ prefix). Use `cmake --build <sherpa-build> --target sherpa-onnx-c-api` only after dependency/native platform fixes. [C API target](https://github.com/k2-fsa/sherpa-onnx/blob/26aa2fa93210376a89de3a65a1a4dd320c37f5e9/sherpa-onnx/c-api/CMakeLists.txt).
5. Explicitly replace/guard sherpa's runtime importer for NuttX. [onnxruntime.cmake](https://github.com/k2-fsa/sherpa-onnx/blob/26aa2fa93210376a89de3a65a1a4dd320c37f5e9/cmake/onnxruntime.cmake) defaults to platform Linux aarch64 download; its preinstalled path prefers .so then .a. Set SHERPA_ONNXRUNTIME_INCLUDE_DIR/LIB_DIR only to reviewed native staging, disallow automatic fallback, and supply an imported INTERFACE target carrying **all** native ORT archives/dependencies. A single found .a does not resolve static closure. Do not use Linux sysroot headers or -ldl/-pthread assumptions blindly.
6. Run actual **board WAV ASR** with current int8 Paraformer,16k mono,feature80,one CPU thread,InputFinished/drain,then destroy. Only after that succeeds enable TTS=ON, compile the extra text/FST stack and run short **board TTS RAM** generation (8k output). Existing prior audit supplies model hashes and memory/path gates. Then link VoiceLink; no PC-assisted inference substitution.

## Required Env/platform changes, not fake POSIX success

Pinned [posix/env.cc](https://github.com/microsoft/onnxruntime/blob/8f5c79cb63f09ef1302e85081093a3fe4da1bc7d/onnxruntime/core/platform/posix/env.cc) uses pthread attributes/create/join (188–223), affinity plus Linux syscall(SYS_gettid) (235–254), nanosleep/EINTR(346), open/fstat/read/seek(357 onward), sysconf pagesize+mmap/munmap(95,445–453), dlopen/dlsym(537,566) and cpuinfo init(602). Select true NuttX implementations: start one-thread CPU, no Linux topology probing/affinity assumptions; dynamic plugin load must explicitly return unsupported when disabled. Regular file bounds/short read/EINTR need real semantics; mmap cannot return fake success. If unmapped loading is selected, verify callers use the read path rather than relying on unsupported mapping. This source audit is not a complete call-graph OS inventory.

Local existing model_reader and explicit1GiB k7_model_arena help but are not installed into ORT. Preserve same-file/immutable mount assumptions; implement allocator ownership and pair releases before model load, without global malloc substitution. C++ exceptions/unwind and libc++/libstdc++ features must match the target; a single-thread request does not prove all third-party libraries avoid pthread or heap calls. Memory need includes237MB ASR weights and180.7MB TTS FAR plus runtime caches; stage ASR and TTS separately first.

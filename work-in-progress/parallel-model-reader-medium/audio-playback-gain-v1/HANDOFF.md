# Prepared-only playback gain

`kd_set_playback_gain(codec, gain_db, deadline)` accepts only0/6/12/18/24dB relative to default DAC-24dB. It requires KD_PREPARED and a nonbusy owner. Values are matched for both DACs:1a/1b=48−2*gain_db, namely30/24/18/0c/00 hexadecimal. OUT2 remains14(-15dB); init[] is untouched. No PCM, route, mute, clock or stream changes are made. Root should start at+6dB and independently decide each later step, not jump to+24dB.

Call after successful prepare and before kd_arm, while amplifier is disabled and streams have not begun. The existing amp(false) callback must drive GPIO LOW and verify actual GPIO readback before returning0. The component cannot independently read GPIO because kd_port has no read-GPIO callback; no fake getter is introduced. Each DAC write is followed immediately by full-byte I2C readback. The gain operation never activates, unmutes or enables amplifier.

Accepted-operation errors, including elapsed deadlines, enter KD_FAULT and clear amp_armed, so kd_arm/kd_enable_amp cannot start playback. Failure after the first channel changes may leave unequal gain registers, but the amplifier remains disabled; no attempted rollback or implicit retry. Stop/reprepare before retry. Failure also attempts bounded amp(false) again when time remains. If GPIO callback itself fails, physical LOW cannot honestly be guaranteed; root must preserve the error and independently recover. With successful initial LOW/readback, later I2C errors never issue an enable.

Invalid arguments and wrong/busy state reject before I/O, preserving the prior owner/state. Do not call while active expecting a forced stop. Expired accepted calls fault without writes. Callbacks remain serialized and synchronous, deadline-bounded by the port; this wrapper cannot forcibly interrupt a stuck callback. Existing kd lifecycle and ownership contract applies.

`input-codec_duplex.c/.h` are exact formal-source snapshots at task start; final delivery hashes freeze them and the candidate. `gain.patch` affects only these two formal paths as a review artifact; it has not been applied. `run_tests.py` invokes GCC C11 strict warnings at O0/O2, compile timeout30s, per-test timeout15s. Existing1309 lifecycle checks run unchanged; new gain test covers all five gains/default preservation/all256 register difference check, all five callback failures, both readback mismatches, timeout at each callback, entry deadline/time rollback, invalid gain/state/busy, FAULT preventing activation. Mocks only, no hardware/SPL validation.

The same-image three-tone audible confirmation comes from root/user. This candidate targets the recorded stream's very low amplitude, not the separate RX/TX FIFO-bank mapping issue. No sample removal or sample-rate relabeling is performed. No SDK, device, formal-source or central-log modification.

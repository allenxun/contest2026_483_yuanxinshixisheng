Root is proceeding with real target lib_iconv.c. This is only a default-OFF backup candidate, not a recommendation to replace that path or a claim that Add registrations were verified.

Fixed CPU provider CMake recursively globs all cpu .cc files, then substitutes reduced registration sources at144–145. It does not automatically remove text/string_normalizer.cc. That file's kernel requires Iconv; original cpu_execution_provider.cc has its declaration355 and registration1563. Therefore skipping FindIconv alone is insufficient.

candidate.patch adds K7_NUTTX_REDUCED_NO_STRING_NORMALIZER (OFF) which requires NuttX+REDUCED_OPS and an actual generated registration file. Before skipping Iconv, it executes k7_verify_no_string_normalizer.py; missing file or any noncomment StringNormalizer reference fails configuration. The same flag removes only string_normalizer.cc before provider target creation. No fake Iconv target/library/function is created, and all defaults/other platforms retain their current behavior. Place the verifier at <ORT>/cmake/k7_verify_no_string_normalizer.py in root's independent stage in addition to applying the patch. The verifier only reads and hashes the actual generated file; it never modifies registrations. Its rejection of any remaining identifier is intentionally conservative.

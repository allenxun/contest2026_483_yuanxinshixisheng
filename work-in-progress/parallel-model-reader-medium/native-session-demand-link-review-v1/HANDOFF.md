# Demand-linked CPU Session versus all-archive audit

Conclusion: the13 missing Abseil symbols in native-voice-link-audit2 are not proof that a CPU Session requires the missing allocator/thread machinery. The audit command passes every common object directly and whole-archives dependency libraries, so it deliberately imports otherwise-unused implementations. There is a concrete official no-sampling path in the default containers, not merely a DISABLE_ABSEIL possibility. A normal demand link is the appropriate next measurement, with all libraries still available. No complete Session link is proven by this review.

## Direct and indirect references

Fixed ORT core plus public include tree has no direct absl::Mutex, absl::CondVar or Abseil LowLevelAlloc call; the matched TensorRTGraphCycles name is unrelated. Default CPU container references are in include/onnxruntime/core/common/inlined_containers{,_fwd}.h and providers/cpu/ml/label_encoder.h:154–161. DISABLE_ABSEIL replaces those with std equivalents, but OrtMutex always uses nsync on this platform. DirectML's remaining explicit Abseil aliases are outside CPU-only scope.

Abseil container/internal/hashtablez_sampler.h:123–125 rejects externally setting ABSL_INTERNAL_HASHTABLEZ_SAMPLE; the frozen header never enables it. :184–201 supplies an empty sampling handle and :209–218 Sample returns null in the default disabled branch, bypassing SampleSlow. Thus default flat_hash usage does not establish a live mutex/LowLevelAlloc edge simply because hashtablez_sampler.cc was compiled. Do not equate compiled source membership with demanded archive members.

If Abseil Mutex does become live, synchronization/mutex.cc:363/383/406/548/1212/1361 references LowLevelAlloc, :579–598 posts/waits via PerThreadSem, and :69/:232 plus deadlock paths use GraphCycles. The current13 residuals are consistent with forcibly including that implementation while platform-disabled supporting files omit definitions. This is not a safe implementation to call without closing those references. Additional possible indirect path: strings/internal/cordz_handle.cc:30/56 and cordz_info.cc:372 use absl::Mutex. No direct ORT CPU Cord call was found; future generated/dependency code can still change closure and needs actual nm/map evidence. Do not assert all Session dependencies are Abseil-free merely from direct source searches.

## Minimal real roots, preserving application scope

1. For the existing common-only probe, pass only its real application/probe object as a strong root. Pack all21 common objects into a normal libonnxruntime_common.a, retain all real dependency archives, and use ordinary library extraction (optionally --start-group/--end-group for circular archive dependencies). Do not pass all21 objects loose or --whole-archive the dependency set. This can test common demand closure, not a Session.
2. For actual Session/Add scope, strong root is the real NuttX application entry calling OrtGetApiBase and its returned API for CreateEnv/CreateSessionOptions/CreateSession or CreateSessionFromArray, input tensor creation, Run, inspection and release. If the application is selected through NuttX's registry rather than ENTRY, preserve that real registry/entry as required by the normal application build; do not rely on an unreferenced dummy main object being retained.
3. Available ORT archive set remains session, optimizer, providers(CPU), framework, graph, util, mlas, common, flatbuffers; plus onnx/onnx_proto, actual protobuf runtime, nsync and the full actual Abseil dependency archive set, and NuttX libc/libc++/ABI/compiler support. Use normal demand extraction and genuine link-group ordering. Keep reduced Add provider registration generated via upstream tooling. Do not arbitrarily remove provider registration/initializers just to make the link pass.
4. Do not reduce C API table entries. onnxruntime_c_api.cc:2729+ preserves the full ABI and OrtGetApiBase:2786 returns the static table. Function pointers in that retained table can retain more functions than only the calls made by the tiny test, even with function/data sections and --gc-sections. A C API linked Session may therefore have a larger closure than a hand-picked C++ method probe; the latter cannot stand in for the intended API integration.

Capture --cref/link map (archive member inclusion reason), --trace-symbol for the missing allocator/thread symbols, and normal final unresolved-symbol errors. Section GC is allowed only with actual app/registry roots retained. An ld -r or successful archive creation is insufficient for executable linkage. Required result: no unresolved13 symbols, map shows mutex/allocator objects absent or supplied by actual reviewed implementations, then real runtime validation. If any live reference remains, report its originating archive member and caller; do not suppress undefined errors, inject stubs, or enable unverified mmap.

DISABLE_ABSEIL comparison requires an entirely separate consistent ORT object rebuild because public C++ container layouts change. It may further reduce actual hash-related members, but the default no-sampling path means first try ordinary linking of the already-built objects. Both variants retain optional libraries as available inputs; only actual extraction decides whether they matter. This conserves existing semantics and avoids treating a whole-archive overapproximation as mandatory platform work.

# DISABLE_ABSEIL: official partial alternative, not a dependency removal switch

Verdict: valid upstream option worth a bounded separate link comparison, but cannot by itself close the LowLevelAlloc platform gap. Do not mark Abseil port complete from the switch.

Fixed ORT1.17.1 cmake/CMakeLists.txt:160 explicitly says Abseil is still linked even when disabled. :161 describes replacing inlined containers with STD containers; :872–873 adds PRIVATE DISABLE_ABSEIL to ORT targets. include/onnxruntime/core/common/inlined_containers.h and inlined_containers_fwd.h replace Abseil maps/sets/vector aliases with standard equivalents. CPU providers/cpu/ml/label_encoder.h:154–170 also supplies std hash/equality/unordered_map. The non-CPU DirectML helper has explicit Abseil aliases but is outside the proposed CPU-only build and not evidence of a CPU dependency.

The actual non-Windows OrtMutex remains nsync (include/onnxruntime/core/platform/ort_mutex.h:105+); this option does not replace or disable it. No direct absl::Mutex runtime call was found in the scanned ORT core CPU/common implementation, but Abseil transitive dependencies can introduce it. cmake/onnxruntime_common.cmake:137 still links ABSEIL_LIBS; framework.cmake:100 and external_deps.cmake:499 likewise retain dependency roots. The fixed ABSEIL_LIBS contains synchronization, time, strings, flags, hash/container libraries. Their target graph does not shrink automatically from DISABLE_ABSEIL.

Abseil synchronization/mutex.cc directly references LowLevelAlloc at363,383,406,548,1212,1361–1363; internal/create_thread_identity.cc:121 allocates through it and its header comment says the file becomes a no-op without required low-level allocation support. Thus merely allowing those sources to compile out does not manufacture definitions required elsewhere. Allocation/platform resolution is still the other agent's task. This review adds no allocator shim and no no-op mutex implementation.

Potential benefit is real but narrower: ORT's switched containers avoid their Abseil hash/sampling references, potentially letting an ordinary demand-driven static link omit some archives/object sections. A declared target dependency is not proof every archive member must be in the final ELF. Conversely retaining ABSEIL_LIBS in CMake is not proof this experiment necessarily fails at runtime; measure actual unresolved symbols and map before concluding. Dependencies used by ONNX/protobuf/re2 and model-specific kernels must be evaluated from their actual built versions. DISABLE_ABSEIL cannot be assumed to remove all of them.

Suggested root experiment, only if useful after current link: new isolated full ORT object set built with onnxruntime_DISABLE_ABSEIL=ON, same CPU/Add configuration and toolchain, retain real upstream dependency libraries, final ELF map/nm compare to baseline for LowLevelAlloc/CreateThreadIdentity/absl::Mutex and all unresolved references. No whole-archive switch just to pull unused dependencies. Still run real session test before acceptance. Do not reuse baseline common/framework/session objects: public container aliases/layouts change, and the upstream compile definition is PRIVATE, so application translation units that include internal/public ORT container-bearing headers must be made consistent explicitly. C API-only clients avoid those C++ layout boundaries, but all ORT objects still require coherent rebuild.

No config/source change, native compilation, target execution or elimination proof performed here. This is a conditional path to reduce actual port surface, not a substitute for needed implementations if symbols remain live.

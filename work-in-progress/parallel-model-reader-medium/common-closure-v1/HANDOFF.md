## Join failure is not safe reclamation

Frozen Env v2 line265 calls std::terminate when native pthread_join returns nonzero. This stops normal destructor continuation in the current C++ control flow; it proves neither worker termination nor safe task-group teardown. EigenNonBlockingThreadPool PoolSignalAllAndWait resets per-thread objects while worker functions retain pool state; surviving workers can still reference it. A terminate handler can call abort, platform task/process termination, or another nonreturning fatal hook. Exactly which tasks, TLS, shared heap and group resources NuttX reclaims depends on the linked C++ runtime implementation, abort implementation, build mode and task-group exit path.

Those abort/terminate/task-group implementation sources are not present among the inspected frozen local inputs, so **safe target-wide stop/reclamation is unproven**. A task-local termination that reclaims group/shared resources while workers survive could cause UAF. Even a full group kill is not graceful shared-service cleanup. The prior host injected-join test proves only handler selection/non-return, not target lifetime safety. Do not report fail-stop as safe recovery; do not resume/reuse an ORT pool after join failure. Before runtime integration root must inspect the exact linked std::terminate -> abort/exit path and sibling-thread handling, or establish a verified platform fatal policy that preserves live referenced storage until whole-domain quiescence. A different Env is not proposed here.

# eMMC 只读接收核心（未集成板端）

**2026-09-10 更新：实现及测试源已迁至 `app/k7emmc/`，初始化、平台配置和独立固件已编译通过，正在 RAM 加载验证。以下为早期接收核心阶段的历史说明。最新以 `docs/eMMC原生只读接入_20260910.md` 和对应真机证据为准。**

新增 `sdhci_command.c`：在调用者已经完成初始化和独占接管的前提下，等待 CMD/DATA inhibit 清除，配置单块 PIO 读取并发送 CMD17；检查控制器错误和 R1 后调用接收核心。限定 32 位扇区地址、容量边界及用户分区前提。命令和数据阶段共用总超时预算；一旦发出命令，失败会锁住后续提交，必须由平台层实际恢复后才能解除。未实现自动恢复，也不能把 ready 标记作为初始化操作的替代。

命令层测试见 `evidence/emmc-source-review-20260910/host-command-test.json`：正常读取、inhibit 超时、无响应、R1 错误、控制器错误、缺少传输结束、跨阶段总截止时间、计时回绕、错误后禁止重试和地址/初始化门禁。两套测试均由 `tools/test_emmc_readonly.py` 执行。

`sdhci_read.c` 收集已经发起、且命令响应已由调用者检查的单块 512 字节 PIO 读取。它不初始化卡、不发 CMD17、不支持 DMA、不注册块设备，也不具备文件访问能力。当前未进入 SDK 同步或固件构建。

所有等待分支与 FIFO 读取都检查同一单调时钟预算；状态矛盾时仍暂停并检查截止时间。错误优先于成功，数据读满后仍等待传输结束并重新检查错误。仅返回 0 时缓冲有效；失败后调用者必须恢复数据路径，不能直接继续提交命令。回调本身必须有界，控制器访问必须独占。MMIO 总线本身不返回的故障不由软件轮询超时解决。

主机验证：运行 `tools/test_emmc_readonly.py`，结果见 `evidence/emmc-source-review-20260910/host-test.json`。覆盖正常读取及边界哨兵、ready/state 不一致、控制器错误、提前结束、缺失结束、读取后错误、计时器回绕、PIO 中途超时和非法参数。

后续按顺序补齐：时钟/复位/电源和安全接管条件；低速卡初始化与容量/RCA；平台错误恢复；单块真机证据；多位置一致性；分区只读解析。CMD17 与 R1 检查目前仅有主机验证。HS400、DMA、文件系统写入均不在当前阶段。

# 原生 openvela 离线 Agent 选型

结论：以当前K7 BSP的已验证能力，主线选择原生openvela重新编译llama.cpp，CPU小模型只负责受约束意图理解，搭配规则优先、可信工具服务和真实状态模板。Linux/RKLLM双系统保留为后续架构备选。本轮不做Linux ABI兼容层、不切换操作系统、不写eMMC。

## 为什么这样选

当前已验证原生4A53+4A72运行及CPU0无线服务，尚无同时运行Linux与openvela的启动、内存/中断/NPU隔离及IPC证据。原厂Android/Linux能够运行无线，不等于双系统已可并行；固定INT8矩阵NPU通过也不等于RKLLM或完整模型运行时可用。双系统不是在现有程序中加一个Linux推理进程即可实现。

官方RKLLM提供RK3576支持及Linux/Android Runtime，仍须配套对应环境。NPU算力标称不能直接证明某个0.5B模型的时延、能耗或双系统4GB内存余量。参考：[RKLLM官方仓库](https://github.com/airockchip/rknn-llm/blob/main/README.md)。

首个候选选指令版Qwen2.5-0.5B-Instruct-GGUF Q4_K_M，官方模型页列有该量化。权重与llama源码后续须固定revision/SHA和许可；目前没有下载锁定权重或完成NuttX推理，不能写成模型已部署。参考：[Qwen官方模型](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF)。

llama.cpp支持GBNF及部分JSON Schema约束，只保证输出格式范围，不保证语义正确或真实设备状态。程序另做工具白名单、参数范围、扫描结果引用、事务归属和执行权限校验。参考：[llama.cpp官方语法约束](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)。不启动HTTP/TCP模型服务。

## 链路与职责

口语 → ASR → 规则解析优先 → 必要时小模型生成候选JSON → 严格参数校验 → 共享设备事务服务 → 真实结果模板 → TTS。

- 唤醒词、密码、紧急停止和明确基础命令继续使用规则路径。密码从输入中提取后不进入模型prompt、模型输出或日志；LLM只引用受控的凭据句柄，不拥有密码。
- Wi-Fi名称来自真实扫描表，模型选择只能引用当前扫描会话内的网络索引。表过期、歧义或不支持时澄清/拒绝，不编造SSID或“已联网”。
- 接受/正在连接/认证失败/DHCP成功分别来自设备事务状态。TTS播报由状态模板生成，成功文案不能由模型自行决定。
- ASR完成后先释放其资源，再执行LLM；LLM结束再释放并加载TTS，复用已有VoiceLink编排策略。先保持单事务，避免三个模型同时常驻。
- 首个LLM探针使用2颗A72，比较4线程；上下文512、输出上限64 token作为初始实验参数，不是已验收性能。无线服务保持CPU0，音频/NPU的其他并发另行测试。

## BSP实际缺口

当前smp-load配置中 HAVE_CXX、USBHOST_MSC、FS_FAT、FS_FATFS均未启用。SDK存在libxx/libcxx选项，但“源码目录存在”不代表已链接运行。系统普通堆约126MiB；显式1GiB模型arena已完成384MiB稀疏测试，不能自动承担llama/ggml malloc，也不能声称4GB全已可用。eMMC已到只读块/BCH接口，尚无可读取GGUF文件的文件系统路径。

主项目文件名核对未找到llama/B0实现。用户表中“仓库已按这条做探针”目前没有本项目证据；若另一任务有实现，应先核对其具体目录、版本和报告，避免重复开发。

## 具体推进顺序

1. **B0-a 平台探针**：新独立配置启用所需C++运行库，验证静态构造、线程/条件变量、时钟、对齐分配及错误释放。随后按固定llama提交逐项处理POSIX依赖。只编译CPU核心，裁掉网络服务和不需要的GPU/OpenMP路径；关闭mmap/mlock作为首个实验方向，具体开关以锁定版本为准。
2. **B0-b 模型读取与分配**：先完成只读大文件路径及随机seek/read/hash核对。可评估USB MSC+FAT作为临时模型载体，避免为首轮模型测试刷写eMMC，但这条USB读盘路径目前也未验收。明确weights/KV/scratch的allocator及arena归属，设置分配上限、对齐与释放计数，保留无线堆余量。
3. **B0-c 真实模型**：固定Qwen权重与llama版本，用文本输入先跑加载→tokenize→prefill→短输出→释放。测量峰值、首token/总时延、2/4线程对比以及BLE/Wi-Fi同时响应。模型不可用时保持规则配网可用，不宣称关键词路由就是LLM Agent。
4. **B1 工具闭环**：先只接wifi_status、扫描请求等已支持工具；共享联网队列、owner/ID、取消/退出栅栏接好后再加入联网操作。扫描在线不支持等限制必须原样返回。用固定中文口语集评估工具选择准确率、歧义处理和非法输出，不能只验JSON能解析。
5. **B2 语音整链**：待实际ASR/TTS库、板载音频或USB音频驱动通过，接入麦克风→ASR→Agent→真实状态→TTS。首次不启用云台动作。源码、模型许可/哈希、配置、原始日志与失败边界统一交付。

双系统方案的重新评估门槛：明确boot链、CPU与内存分配表、NPU独占/复位机制、双方同存活证据、共享内存缓存一致性和IPC故障隔离，再用同一业务测端到端时延与功耗；目前不投入这条移植主线。
